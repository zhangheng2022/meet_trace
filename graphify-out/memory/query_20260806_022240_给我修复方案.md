# Q: 给我修复方案

## Answer

Expanded from original query via graph vocab: [recording, waveform, level, batch, interval, queue, timer, preview, dispatcher, persist, flush, continuity]. 推荐保留250ms事实音频批量落盘与flush，不能让UI节奏反向控制事实链。ReliableRecordingService在成功写盘后将同一批PCM作为一个连续RecordingPcmChunk投递，并将PcmAudioLevelMeter与ASR预览拆为独立dispatcher，避免平台小chunk在同一批突发时溢出共享队列，也避免ASR积压拖住音量链。RecordingSessionViewModel增加100ms周期的有界音量展示队列，每tick只发布一个RecordingAudioLevel，最多保留约500ms并丢弃最旧样本；暂停、停止和dispose清队列并取消timer。RecordingAudioWaveform把140ms easeOutCubic改为约100ms线性过渡，使每个采样周期持续运动。测试覆盖生产250ms批处理、突发样本匀速发布、队列过载最新优先、暂停/释放、ASR阻塞不影响波形、事实音频100%完整及先持久化后反馈；真机验证显示间隔80-120ms、稳定录音无超过200ms停顿、波形延迟不超过500ms且帧耗时达标。不要仅把factCommitInterval改为100ms，不要在写盘前用采集PCM驱动波形，也不要只改动画时长。
