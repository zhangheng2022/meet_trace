- ViewModel 通过 `MeetTraceDependencies` 扩展方法创建（如 `createMeetingListViewModel()`），而非直接 new，保证依赖注入一致性。
- 所有异步操作使用 `unawaited(...)` 启动并配合 `whenComplete` 或 try/finally 确保资源释放（dispose）。
- 领域层保持纯 Dart，通过 `test/architecture/layer_boundaries_test.dart` 的 import 正则断言禁止引入 flutter/forui 包。
- 错误处理采用 FutureBuilder + 特定异常类型（如 `UnsupportedAlphaInstallationException`）区分启动失败场景。
- 数据服务通过构造函数注入依赖（layout、repository、service），避免全局单例，便于测试时替换 fake。
- Feature 目录按 `view_models/` 和 `views/` 双目录组织，ViewModel 与 View 一一对应并通过构造函数传递。
