# 会迹（MeetTrace）端侧双模型转录技术方案

> 版本：V1.1
> 状态：当前技术基线
> 更新日期：2026-07-27
> 上游需求：[会迹（MeetTrace）Android + iOS Alpha PRD V0.6](./会迹_MeetTrace_Alpha_PRD_无登录版.md)
> 下游计划：[Codex Alpha 开发步骤](./Codex_Alpha_开发步骤.md)

## 1. 目的与现状

本文定义 Android + iOS Alpha 的端侧录音、双模型 ASR、最终转录、模型管理和降级架构。

当前仓库已有 Flutter/Forui 应用壳、领域接口、本地事实存储、可靠事实录音和隔离在 data/service 层的双模型生命周期：标准模型随平台安装包准备，高级模型支持空间/网络预检、HTTPS 续传、严格校验、原子激活、租约和安全删除。Step 01～18 的现有真机与发布证据来自 Android；这些实现为 iOS 复用业务层与官方 Flutter 插件提供基础，但不能替代 iOS arm64、后台音频、系统中断、双模型和安装包审计。

## 2. 不可破坏的约束

1. 本地完整音频是唯一事实源。
2. 音频持久化优先于 ASR 投递。
3. ASR 慢、积压、异常退出或模型损坏时录音继续。
4. 临时转录可丢弃和重建，音频块不可丢失。
5. 最终转录必须从完整音频生成。
6. AI 总结只能读取激活的最终转录快照。
7. 会议开始后模型锁定，不混合两个模型的输出。
8. UI 只依赖 ViewModel/Repository，不直接调用 ONNX、文件系统或 HTTP。

## 3. 模型基线

| 层级 | modelId | 运行时 | 分发 | 目标 |
|---|---|---|---|---|
| 标准 | `sherpa-onnx-paraformer-zh-small-2024-03-09` | sherpa-onnx | Android/iOS 安装包内置 | 低功耗、低端设备、普通话/英语 |
| 高级 | `sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25` | sherpa-onnx | 按需下载 | 准确率优先、更多语言能力 |

- 标准模型 INT8 ONNX 文件约 79 MB，发布门槛为模型资源不超过 100 MB（公共运行库除外）。
- 高级模型完整资源约 941 MB，产品预检按至少 2 GB 可用空间执行。
- Step 01 实测标准模型运行必需文件为 81,904,027 字节，高级模型运行必需文件为 987,015,347 字节；双模型发布 Manifest 已按最终文件大小和 SHA-256 固定。
- 具体文件、许可、下载地址和哈希统一进入版本化 Manifest，业务代码不得散落硬编码。
- 方言、多语言、标点、时间戳等能力只在真机和语料验证后写入 `capabilities`。

## 5. 领域模型

### 5.1 模型描述

```dart
enum AsrModelTier { standard, advanced }
enum AsrInstallationType { bundled, downloadable }

final class AsrModelDescriptor {
  AsrModelDescriptor({
    required this.modelId,
    required this.displayName,
    required this.tier,
    required this.version,
    required this.supportedLanguages,
    required this.installationType,
    required this.requiredBytes,
    required this.capabilities,
  });

  final String modelId;
  final String displayName;
  final AsrModelTier tier;
  final String version;
  final List<String> supportedLanguages;
  final AsrInstallationType installationType;
  final int requiredBytes;
  final Set<String> capabilities;
}
```

`AsrModelRegistry` 是已发布模型元数据的单一入口。领域层只使用 `modelId`，不依赖模型文件名。

### 5.2 会议模型归属

```text
requestedModelId       // 用户最初选择
recordingModelId       // 开始前确认的实际模型
recordingModelVersion  // 本场锁定版本
```

若高级模型在开始前不可用，只有用户明确确认后才允许：

```text
requestedModelId = qwen3...
recordingModelId = paraformer...
```

开始录音后 `recordingModelId` 和版本不可变。每个最终快照另外保存实际模型，支持历史音频使用其他已安装模型重新处理。

### 5.3 转录对象

两种模型统一使用 VAD 的全局 `startMs/endMs`。不得把未验证的模型内部时间戳能力当作产品保证。

### 5.4 Step 02 实现边界

- `lib/domain/models/` 已实现不可变的会议、转录、总结、模型描述、模型安装、音频源、状态机和结构化错误对象。
- 会议保存全局默认模型对应的实际录音模型和版本；默认模型不可用时阻止开始，不自动回退，进入录音状态后模型选择锁定。
- 只有 `final + complete + active` 的快照可作为总结输入；激活新最终快照时清除旧摘要引用，失败快照不能改变旧活动快照。
- 会议、录音、处理和模型安装的合法迁移集中在 `workflow_states.dart`，调用方不能通过直接赋值绕过。
- `lib/data/services/asr/asr_engine.dart` 和 `lib/data/repositories/repository_contracts.dart` 只定义纯 Dart 抽象端口，不包含 ONNX、数据库或平台实现。
- `AsrModelDescriptor`、快照片段、总结证据和诊断上下文均做防御性复制，避免外部集合修改领域状态。

## 6. ASR 抽象

```dart
abstract interface class AsrEngine {
  AsrModelDescriptor get descriptor;

  Future<void> initialize();

  Stream<TranscriptEvent> get events;
  Stream<AsrFinalizationProgress> get finalizationProgress;
  AsrDeviceRiskState get deviceRisk;
  Stream<AsrDeviceRiskState> get deviceRisks;
  AsrEngineMetrics get metrics;
  List<AsrWindowDiagnostic> get diagnostics;

  Future<void> acceptAudio(
    Float32List samples, {
    required int sampleRate,
    required int startMs,
  });

  Future<TranscriptSnapshot> finalizeMeeting(
    AudioSource source, {
    required String meetingId,
  });

  void cancel();
  Future<void> dispose();
}
```

- `ParaformerStandardAsrEngine` 已实现标准模型初始化、不超过 15 秒的片段识别、全局区间事件和完整事实 PCM16 音频处理。
- `QwenAdvancedAsrEngine` 已实现高级活动版本校验、模型使用租约、风险门槛、片段识别和完整音频处理。
- 两个薄 Engine 复用 `SherpaOnnxAsrEngine` 公共 Dart 核心；Paraformer 只持有标准模型配置，Qwen 只持有高级模型配置与生命周期钩子。
- `SherpaOnnxAsrEngineFactory` 只根据已经确认的模型 ID 和 Registry 精确版本组装 Engine；它不读取全局默认、不做回退，也不把具体 Engine 暴露给 UI/ViewModel。
- 设置 ViewModel 只允许已安装模型成为后续会议默认；开始会议 ViewModel 只读取该默认值并直接创建会议，不接受本场覆盖。
- 默认高级模型不可用时阻止创建会议并引导用户前往设置处理，不自动回退；录音态会议模型与版本不可修改。
- `AsrCoordinator` 负责队列、状态、生命周期和指标，不包含具体模型分支。
- ViewModel 不得导入以上两个具体 Engine。

## 7. 官方 sherpa_onnx Flutter 包集成

### 7.1 依赖边界

- `pubspec.yaml` 直接依赖官方 `sherpa_onnx` Flutter/Dart 包。
- 依赖版本固定为 Day 1 真机 Spike 验证通过的版本，不使用无上限浮动版本。
- 官方包负责 Dart FFI、Android 原生运行库和 ABI 集成。
- 会迹（MeetTrace）不维护 JNI、ffigen、C API 绑定、C/C++ 构建链或私有 ABI 声明，也不把原生库复制到项目 `jniLibs`。
- `ParaformerStandardAsrEngine` 和 `QwenAdvancedAsrEngine` 是 Dart 业务适配器，不包含 `DynamicLibrary.open`、C 指针或 JNI 调用。
- 官方包能力不足时，先验证官方稳定版本和公开 API，再调整依赖版本或目标模型并更新 PRD；不得自建原生桥接。

### 7.2 Dart 适配器职责

- 从 ModelManager 获取已校验的模型目录和版本。
- 将 `AsrModelDescriptor` 转换为官方包公开的识别器配置。
- 通过官方 API 完成初始化、音频输入、结果读取、资源释放和应用级取消。
- 将官方结果转换为统一 `TranscriptEvent` 和 `TranscriptSnapshot`。
- 将第三方异常转换为结构化应用错误，不向 UI 暴露包类型。
- 为单元测试注入 fake adapter；普通单元测试不加载原生运行库。

当前公共 adapter 已实现：

- `main.dart` 启动时通过 `SherpaOnnxRuntimeInitializer` 在主 isolate 一次性调用官方 `initBindings()`；异常只形成可重试 `AppFailure`，应用壳和录音能力继续可用。
- `SherpaOnnxRecognizerConfig` 只保存模型身份、版本、已校验路径、线程数和 Qwen 长度上限，不携带官方对象、原生指针或 UI 类型。
- 每个 adapter 创建一个长生命周期推理 isolate；该 isolate 按官方要求独立初始化 bindings、持有一个 `OfflineRecognizer`，并在 dispose 时显式 `free`。
- PCM 使用 `TransferableTypedData` 进入 worker；同一 adapter 的识别请求确定性串行执行，worker 异常退出会完成所有等待任务，不产生永久悬挂。
- 官方初始化、推理和释放异常只映射为包含模型 ID/版本、阶段、恢复性和错误类型的 `SherpaOnnxAdapterException/AppFailure`。
- 应用级取消停止接收排队任务并丢弃活动结果。官方离线 `decode` 没有抢占 API，当前活动窗口仍在后台完成；因此 Step 09/10 必须继续执行 15 秒窗口上限。
- 官方结果到 `TranscriptEvent`/`TranscriptSnapshot` 的业务转换属于 Step 09/10 具体 Engine，不在公共 adapter 中耦合。

### 7.3 Android + iOS 构建验证

- 原生运行库由官方 Flutter 包及其平台依赖提供，会迹（MeetTrace）只负责验证构建结果。
- Android 至少验证 `arm64-v8a`；构建后检查 ABI、重复原生库、APK 体积和许可证。
- iOS 至少验证真机 arm64 与目标最低系统版本；在 macOS/Xcode 环境检查 xcframework、
  标准模型资产、隐私用途说明、签名配置和 App Store 隐私清单。
- 两个平台安装包必须包含内置标准模型，不得包含按需下载的高级模型文件。
- 依赖升级必须分别重新执行两个模型的初始化、释放、重复创建和安装包内容回归。
- Android 既有检查脚本继续断言 `arm64-v8a`、Flutter 聚合许可证 `NOTICES.Z`、
  标准模型资产、高级权重缺失和重复原生库；iOS 建立等价脚本前发布门禁保持 `blocked`。

### 7.4 并发

- 音频写入在独立的高优先级执行链完成。
- 通过官方 Dart API 发起的 ONNX 推理必须调度到不阻塞 UI 和录音写入关键路径的执行链。
- 单场会议同一时刻只允许一个活动 ASR Engine。
- Engine 异常必须转换为结构化错误，不得导致录音 Service 退出。
- 公共 adapter 的推理 isolate 与录音文件写入链无共享队列；PCM 传输采用所有权转移副本，worker 不持有录音文件句柄。

### 7.5 Step 01 真机校准

- 官方包固定为真机验证过的 `sherpa_onnx` 1.13.4；包与原生运行库版本一致。
- 离线识别不得把 5 分钟完整音频作为一个 utterance 直接输入。Paraformer 上游建议单段输入短于 20 秒；Spike 将统一窗口从 30 秒缩短为 15 秒后，两轮均从 7/10 提升为 20/20 可读。
- 正式 VAD 为两个模型生成相同的全局时间区间，单次识别窗口硬上限为 15 秒；过长语音段须重叠切分并确定性合并。
- Mi 10 上 Paraformer 15 秒窗口首结果为 317～324 ms、RTF 约 0.0214、峰值 RSS 约 455 MiB；正式 Engine 必须逐窗口保留错误/空结果指标并从事实音频支持重试。
- Mi 10 上 Qwen3-ASR 首窗口结果约 18～20 秒、峰值 RSS 约 2.92 GiB，不满足会中“句后准实时”；高级模型必须具备设备能力门槛、积压状态和内存/温控风险提示，不得阻塞录音或自动切换模型。
- `AndroidProcAsrDeviceRiskMonitor` 只读取 Android 公开 `/proc/meminfo`、进程 RSS 和可读 thermal zone，不维护原生桥接；总内存低于 4 GiB、可用内存不足 512 MiB 或温度达到 80°C 时阻止高级推理，constrained/warning/serious 作为可观察风险继续运行。平台节点不可读时对应维度保持 unknown，风险变化不得修改会议锁定的模型身份。
- `createPlatformAsrDeviceRiskMonitor` 在 data/service 装配层选择平台实现。iOS 在没有
  等价公开 Dart 指标前使用 `PortableAsrDeviceRiskMonitor`：保留进程 RSS，把设备能力
  标记为 constrained、内存与温控标记为 unknown；未知本身不阻止推理，但必须显示风险，
  直到 iOS 真机门槛提供可验证的支持矩阵。
- 录音连续性探针必须先于高内存模型测试运行；应用架构中录音写入链与 ASR Isolate 始终独立，不能依赖测试顺序保证安全。
- 详细原始指标和限制见 [Step 01 双模型真机 Spike](./quality/Step_01_双模型真机_Spike.md)。

## 8. 音频与 VAD 数据链

### 8.1 事实音频

- 采集格式：16 kHz、单声道、PCM16。
- `RecordPcmAudioCapture` 只适配官方 `record` 7.1.1 公开 Dart API，不维护自建 JNI、FFI 或原生录音桥接。
- Android 使用公开 `flutter_foreground_task` 10.0.0 的 microphone service type、常驻通知和 wake lock 维持后台录音；服务不承载音频数据或 ASR。
- iOS 使用 `record` 的 AVFoundation 实现与 `UIBackgroundModes/audio` 维持活跃音频会话，
  不启动 Android foreground-service 语义。锁屏、切后台和系统音频中断需要独立真机验证；
  用户从任务切换器强制结束 App 后系统会终止录音，重启时只恢复已经持久化的事实音频。
- 音频块先写入 `recording.pcm.tmp` 并 flush，再以 `checkpoint.json.next/current/previous` 双代切换持久化字节数，最后投递预览副本。
- 结束时 flush、fsync/等价持久化、关闭并原子封存。
- 暂停不填充静音；恢复后的时间轴只按已持久化 PCM 样本连续累计。
- 预检至少保留 128 MiB 可用空间；权限或空间不足时不创建事实音频。
- 来电和音频焦点中断由 `AudioInterruptionMode.pauseResume` 交给官方录音包处理。
- 异常退出恢复时舍弃不足一个 PCM16 样本的尾字节，封存可恢复部分并按真实字节数计算时长；数据库只在最终文件可验证后进入处理态。

### 8.2 分发顺序

```text
Microphone chunk
  1. durable writer
  2. update recovery checkpoint
  3. VAD / preview queue
```

第 3 步失败不得回滚前两步。

当前 preview dispatcher 上限为 4 个块；消费端阻塞、抛错或队列满时可丢弃预览，事实写入链不等待 preview。

### 8.3 VAD

- Silero VAD 产生统一、单调递增的音频时间区间。
- VAD 窗口保留少量前后文，具体值由语料评测决定。
- 单次识别窗口硬上限为 15 秒；过长语音段按重叠窗口切分，合并必须确定性去重。
- VAD 结果用于两个模型，确保双模型评测时间边界一致。
- 当前 `SileroVadSegmenter` 通过官方 `VoiceActivityDetector` 固定使用 16 kHz、512 样本窗口、单线程 CPU 和 15 秒最大语音段；局部样本位置映射到事实音频全局时间轴。
- `AsrPreviewWindowPlanner` 默认保留前后各 200 ms，超过 15 秒时使用 500 ms 重叠；重叠文本按最长后缀/前缀规则确定性合并为同一稳定片段 ID。
- 官方 `silero_vad.int8.onnx` 以 `212,860` 字节内置资产进入 APK；独立 Manifest 固定版本 `2025-07-11`、SHA-256 `c36d490aff5ab924ca6c7aeec4d8f6bd3d22db6fa17611b9c5b17eae58ac3a20`、GitHub release asset ID `271935990`、来源时间戳、NOTICE 和 MIT 文本。
- `BundledSileroVadModelService` 先复制到应用私有临时目录，使用严格文件集、大小和 SHA-256 校验，再原子切换为可加载路径；损坏资产不形成最终目录，已验证版本不重复复制。
- Android 16 x86_64 模拟器已使用包内真实权重连续两轮完成初始化、512 样本连续输入、尾段 flush、释放和复用；Step 13 又走通模拟器真实麦克风权限、21 秒录音、暂停/恢复和封存。实体设备麦克风阈值、功耗与温控仍在 Step 18 端到端验收中校准。

### 8.4 有界预览队列

- 队列容量用音频时长而不是只用任务数衡量。
- 达到高水位后停止投递或丢弃最旧的可重建预览任务。
- 不删除事实音频，不把会议标记为失败。
- 暴露 `queuedAudioMs`、`droppedPreviewWindows` 和 `previewLagMs`。
- 队列恢复后可以从当前时间继续预览，无需补齐所有旧预览。
- 当前 `AsrPreviewCoordinator` 默认最大排队 30 秒、高水位 15 秒、低水位 5 秒；超限时只丢最旧待处理预览窗口，回落到低水位后恢复。
- Coordinator 同时暴露 VAD 片段数、已处理/丢弃窗口数和最后错误码；VAD 或 Engine 失败后进入 `recordingOnly`，不向可靠录音链传播异常。

## 9. 临时与最终转录

### 9.1 会中临时转录

- 目标是“句后准实时”，不是逐字流式字幕。
- 每个 VAD 片段带稳定 ID 和全局时间区间。
- UI 按 `startMs`、序号进行确定性排序。
- 同一窗口的修订替换旧临时文本，不产生无界重复记录。
- Engine 失败后状态转为“仅录音/转录暂停”，不切换模型。

### 9.2 会后最终转录

1. 确认事实音频已封存。
2. 创建 `processing` 快照记录。
3. 从完整音频顺序读取并按锁定模型推理。
4. 合并、排序、校验时间区间。
5. 在事务中写入完整快照。
6. 成功后原子切换 `activeTranscriptSnapshotId`。
7. 失败时保留旧快照和音频。

重新转录时可选择另一个已安装模型，但必须生成新快照，并记录 `actualModelId/actualModelVersion`。不得将不同模型的片段拼入同一快照。

当前实现由 `FinalTranscriptionService` 统一编排：处理尝试先创建稳定 ID 的 `processing` 快照，再把同一 ID 传给精确模型 Engine；Engine 只接收会议的事实 PCM 路径和真实时长。编排层校验会议、快照、模型/版本、片段边界和相邻片段重叠后，才调用 `saveFinalAndActivate`。该 SQLite 事务同时保存完整快照、以预期旧 active ID 做 CAS、将会议置为 `completed` 并清除旧摘要；任一步失败均把本次尝试标为 `failed`，不改变旧活动快照。

### 9.3 说话人分离降级

`SpeakerDiarizationService` 是 data/service 层的纯 Dart 端口，暴露能力状态并接收完整事实音频；`SpeakerDiarizationCoordinator` 只允许处理当前活动、`final + complete` 的最终快照。服务返回带 `startMs/endMs/speakerId` 的时间区间后，编排层按最大重叠时长为每个既有转录片段选择说话人；无重叠片段使用 `speaker-1`。映射只通过 Repository 更新 `speaker_id`，不得改变片段 ID、原文、时间轴、置信度或 ASR 模型 ID/版本。

自动能力使用 `speaker_diarization_enabled` 全局开关，默认关闭。任务以 `speaker-diarization-<snapshotId>` 保存到 `processing_tasks`；完成、失败和错误码可在重新打开详情页后恢复。超时、空结果、资源不足、服务异常或能力不可用都降级为单一说话人，最终快照继续保持 `complete`，后续总结不得因此阻塞。用户可按当前说话人批量重命名标签；SQLite 事务只接受属于目标已完成最终快照的片段 ID 和 1～80 字符标签。

当前 Alpha 没有在 PRD、Registry 或发布 Manifest 中批准独立的说话人模型，因此生产装配使用 `UnavailableSpeakerDiarizationService`，页面明确显示“当前构建未配置已验证的本地说话人模型”并保留人工标签。未来只有在模型来源、许可、Manifest、体积和设备门槛更新后，才能替换该 Dart 端口实现；不得自建 JNI/FFI 原生桥接绕过此边界。

## 10. 模型生命周期

### 10.1 Manifest

Manifest v1 顶层包含 `schemaVersion`、`minAppVersion` 和 `models`。每个模型必须包含：

- 与 `AsrModelRegistry` 完全一致的 `modelId`、`version`、`tier`、`installationType` 和 `requiredBytes`。
- 非空且路径不重复的 `files`；每项包含安全相对 `path`、正整数 `bytes`、64 位小写十六进制 `sha256` 和 `url`。
- 非空 `license.name` 以及指向仓库内声明文件的安全相对 `license.noticePath`。

可下载模型只接受 HTTPS URL，内置模型只接受 `asset://` URL。逐文件字节数之和必须等于 `requiredBytes`；客户端拒绝未知 schema、最低 App 版本过高、重复模型 ID、路径穿越、占位符以及任何与 Registry 分叉的字段。

`ModelFileVerifier` 对准备目录执行严格文件集、字节数和 SHA-256 校验，多余文件同样视为失败。双模型发布 Manifest 位于 `assets/models/manifest.json`：标准模型使用最终打包资产，高级模型六个文件使用固定 revision 的 HTTPS URL、真实文件哈希和许可 NOTICE，不含占位条目。

### 10.2 内置标准模型

1. 标准模型随 APK 进入只读 assets。
2. 首次启动或首次转录前复制到私有临时目录。
3. 逐文件校验大小和 SHA-256。
4. 原子重命名为版本目录。
5. 更新 `ModelInstallation`。
6. 标准模型不能由用户删除。

若 assets 读取、空间或校验失败，系统进入仅录音模式并保留错误码。

当前实现由 `FlutterModelAssetSource` 将 `asset://` URL 映射为 Flutter asset key，`BundledModelPreparationService` 负责以下顺序：

```text
检查现有版本
  → 清理目标版本临时目录
  → 逐文件读取 asset、写入和 flush
  → 严格校验文件集、字节数、SHA-256
  → 原子重命名为版本目录
  → 保存 ModelInstallation(installed)
```

数据库保存失败时不回滚已通过校验的最终目录；下次准备先重新校验并收养该目录。校验失败只保存 `failed`，不形成最终目录或 `installed`。已正确安装时不重复读取 asset。

`model.int8.onnx` 与 `tokens.txt` 合计 `81,904,027` 字节，已注册为显式 Flutter assets，并由真实资产测试核对发布 Manifest 的大小、SHA-256 和严格文件集。精确上游 `crazyant/speech_paraformer_asr_nat-zh-cn-16k-common-vocab8358-onnx` 的 ModelScope API 仍未声明 `License`、`LicenseName` 和 `LicenseLink`；产品负责人已明确批准将权重用于 Android Alpha APK，来源、归档哈希和未决许可状态记录在 `assets/licenses/paraformer-small-NOTICE.txt`。公开分发前仍须完成再分发许可确认。

### 10.3 高级模型按需下载

状态机：

```text
notInstalled
  → checking
  → downloading
  → verifying
  → installed

downloading ↔ paused
任意活动状态 → failed → retry
installed → updateAvailable → downloading(new version)
installed → deleting → notInstalled
```

- 下载前通过 `disk_space_2` 查询应用支持目录所在卷的可用空间，由 data/service 层统一把插件返回的 MiB 保守换算为字节并检查至少 2 GiB；通过 `connectivity_plus` 区分无网络、非计费网络和需用户确认的移动/未知网络。连接类型只用于提示，真实网络错误仍由 HTTP 层处理。
- `HttpModelFileDownloader` 使用 `dart:io HttpClient` 和 HTTPS，按文件写入版本化临时目录；服务器支持 Range 时从已有字节续传。
- 取消保留可续传临时文件并记录 `paused`；网络失败记录可重试错误；哈希失败删除错误临时版本，均不触碰旧活动版本。
- 全部六个文件通过严格文件集、大小和 SHA-256 校验后，临时目录原子重命名为版本目录，再由 SQLite 单事务切换 `active_model_versions`。
- 正在录音或处理的版本持有带过期时间的 `model_usage_leases`；有效租约释放前不删除，崩溃遗留租约到期后可清理。
- 高级 Engine 创建时按 owner 获取活动版本租约，同 owner 的有效租约视为冲突；每次识别前接近到期则续租，释放 Engine 时删除租约。活动版本之后发生切换时，已锁定会议继续使用其持有租约的版本，不自动换模型。
- 删除只清理目标版本临时/最终目录、安装记录和匹配活动指针；会议、转录和总结表不依赖安装记录，因此历史内容保持。

### 10.4 版本兼容

- 标准模型版本随 App 发布。
- 高级模型由远端 Manifest 更新，但客户端必须校验 `schemaVersion` 和最低 App 版本。
- 历史会议保存实际版本，不依赖当前默认版本反推。
- 模型删除只删除模型文件，不删除历史会议和转录。

## 11. 状态、错误与降级

统一错误至少包含：

```text
code
stage
modelId?
modelVersion?
recoverability
userAction
diagnosticContext
```

| 故障 | 行为 |
|---|---|
| 标准模型缺失/损坏 | 仅录音；提示修复或重装 |
| 高级模型下载失败 | 保留旧版本；可重试或改用标准模型 |
| 高级模型校验失败 | 删除临时版本；不覆盖已安装版本 |
| 开始前高级模型初始化失败 | 由用户确认改用标准模型或取消 |
| 录音中 Engine 失败 | 录音继续；临时转录停止；不自动切换 |
| 预览队列积压 | 丢弃可重建预览；记录指标 |
| 最终转录失败 | 保留音频和旧快照；允许重试或完整重转 |
| 说话人分离失败 | 使用未分离最终转录继续 |
| 总结失败 | 最终转录保持可用；单独重试总结 |

所有回退必须在数据和 UI 中可见，不能静默更换模型。

## 12. 本地存储和事务

正式选型使用 `sqflite` 2.4.3 保存会议、模型安装、全局设置、快照、片段、摘要和任务状态，文件系统保存音频和模型。Android 使用 `sqflite` 平台实现；普通单元测试使用 `sqflite_common_ffi` 2.3.7 与 `sqlite3` 2.9.4 的内存数据库，避免测试依赖模拟器或运行时下载原生库。App 私有根目录由 `path_provider` 2.1.6 提供；Android 实现暂固定为 `path_provider_android` 2.2.23，避免 2.3.x JNI 实现在 Android 11 Mi 10 上触发 `libdartjni.so` 崩溃，升级前必须复跑该设备。

### 12.1 SQLite v1 基础、v2 设置与 v3 模型生命周期

数据库文件为 `<application-support>/meettrace/database/meettrace.db`，打开时强制启用外键。v1 建立：

- `meetings`
- `transcript_snapshots`
- `transcript_segments`
- `summaries`
- `summary_items`
- `summary_evidence`
- `model_installations`
- `processing_tasks`

v2 增加 `app_settings`，以 `default_asr_model_id` 保存全局默认模型，以 `speaker_diarization_enabled` 保存自动说话人开关；没有记录时分别使用 Registry 标准模型和 `false`，保存模型前必须确认模型 ID 已注册。

v3 增加 `active_model_versions` 和 `model_usage_leases`。安装记录与活动版本在同一事务中写入；租约记录 `owner_id`、获取时间和过期时间，外键只关联对应模型版本。

v4 为 `summaries` 增加 `title`。完成摘要与当前最终快照激活时，在同一事务中仅将仍为“待生成标题”的会议更新为摘要标题；用户已经重命名的标题保持不变。

v1→v3 迁移依次新增设置和模型生命周期表并保留现有数据。会议删除通过外键只级联对应快照、片段、总结和处理任务。Repository 使用 update/insert，不使用会先删除旧行的 `INSERT OR REPLACE`，避免意外触发级联删除。最终快照写入和 `activeTranscriptSnapshotId` 切换在同一事务中，并用旧活动快照 ID 做并发检查；说话人映射使用受限更新，只修改已完成最终快照现有片段的 `speaker_id`。

### 12.2 App 私有文件布局

```text
<application-support>/meettrace/
  database/meettrace.db
  meetings/<meetingId>/audio/
    recording.pcm.tmp
    fact.pcm
  models/
    .tmp/<modelId>/<version>/
    <modelId>/<version>/
```

ID 只能作为安全的单一路径片段，禁止 `..`、斜杠、反斜杠和空字节。

### 12.3 耐久提交

关键提交顺序：

```text
write temp file
  → verify/flush
  → atomic rename
  → database transaction references final path
```

临时文件必须存在、非空并完成 flush；原子重命名后再次核对最终文件，再执行数据库引用事务。数据库事务失败时最终文件作为可恢复孤儿保留，绝不写入指向不存在文件的引用。

### 12.4 启动恢复

启动恢复器扫描：

- `recording` 且进程已不存在的会议：存在临时/最终事实音频时封存并进入 `processing`，文件缺失或为空时记录结构化失败。
- `running` 且租约过期的处理任务：清除租约并重新进入 `queued`。
- `models/.tmp` 下未完成的模型版本目录：只在校验目标仍位于临时根目录后递归清理。
- 已完成但未激活的最终转录快照：激活每场会议最新快照，将会议恢复为 `completed`，并清除旧摘要引用。

恢复操作必须幂等；相同残留第二次扫描的变更数必须为 0。

依赖依据：[sqflite](https://pub.dev/packages/sqflite)、[sqflite_common_ffi](https://pub.dev/packages/sqflite_common_ffi)、[path_provider](https://pub.dev/packages/path_provider)。

## 13. AI 总结边界

- `GenerateSummaryUseCase` 只接收 `final + active + complete` 的快照。
- 本地模型总结可后续扩展，不在双 ASR 模型范围内。
- `SummaryGenerationRequest` 只包含 schema 版本和片段的 ID、最终文本、可选说话人标签；类型层不允许携带会议 ID、快照 ID、本地时间戳、音频路径或音频字节。
- 服务结构化返回概览、关键结论、行动项和 evidence segment IDs，不接受服务返回的时间戳或引文作为本地事实。
- `GenerateSummaryUseCase` 使用当前最终快照把 evidence ID 映射成本地 `startMs/endMs/quote`，去重并丢弃未知 ID。
- `SqfliteSummaryRepository.saveAndActivate` 在同一事务内重新校验最终快照、逐条核对证据 ID/时间/原文、保存完整摘要并以当前转录 ID 做 CAS 激活；任一步失败均不改变会议活动摘要。
- 新最终转录成功激活后，旧的已完成摘要标记为 `stale` 并清除活动引用。
- 生成任务状态独立持久化；超时或服务异常只把摘要任务标记失败，最终转录保持可用并允许重试。
- 无安全网关时生产装配使用 `UnavailableSummaryGenerationService` 显式关闭功能，禁止将永久 API 密钥写入 App。
- 无有效证据的结论标记“待核对”。

## 14. 结果页与数据控制

- 转录编辑不覆盖活动快照：`ReviseFinalTranscriptUseCase` 要求提交当前快照的完整片段集合，生成新的最终快照和片段 ID，再通过 Repository CAS 原子激活；旧摘要随版本切换标记 `stale`。
- 证据播放只信任当前本地最终快照。片段 ID、时间范围或引文任一不匹配即拒绝播放；PCM16 区间按块写入临时 WAV，避免完整录音一次性进入内存。
- 分享文档只由会议标题、当前最终转录和总结构造。纯文本与 Markdown 都明确不包含原始音频；平台分享只接收文本，不传文件路径或音频附件。
- 会议删除先将 `meetings/<meetingId>` 原子移动到同根暂存目录，再删除数据库记录；数据库事务失败则恢复目录，成功后才递归清理暂存目录。
- 高级模型目录与会议历史解耦。删除 Qwen3-ASR 只清理模型安装/活动版本；历史会议继续保留实际模型 ID 和版本，不伪造回退结果。
- 设置页存储统计只读取应用私有根目录的字节数。诊断导出采用固定白名单，只允许容量、状态计数、模型 ID/版本/状态/字节和错误码，不允许标题、正文、音频、会议 ID或本地路径。
- 平台能力使用公开插件：音频输出使用 `audioplayers`，文本分享使用 `share_plus`；继续禁止项目自建 JNI、FFI 或手工 `jniLibs`。

## 18. 发布检查

- 使用 `EvaluateAlphaReleaseUseCase` 对发布证据执行三态门禁：不达标为 `noGo`，证据缺失为 `blocked`，全部通过才为 `go`。RTF 和句后延迟至少 20 个样本才计算最近秩 P50/P95。
- 发布门禁输入只保存匿名语料/设备标识、原始指标引用、数值和 AT 证据引用；原音频、完整转录和摘要正文不得进入仓库。
- Manifest 没有占位符，全部文件哈希匹配。
- Android APK 与 iOS 构建产物包含标准模型和官方包提供的目标架构原生库，不包含高级模型文件或重复原生库。
- 两个 Engine 能从 Factory 独立创建和释放。
- 录音故障注入证明 ASR 不影响事实音频。
- 所有最终快照记录实际模型和版本。
- 云端总结未配置安全网关时保持关闭。
- 许可声明与模型、官方包及其原生运行库版本一致。
- `flutter analyze`、`flutter test`、Android/iOS 真机集成测试、Debug APK 和 iOS
  `--no-codesign` 构建通过。

当前执行状态和未闭环证据见 [Step 18 双模型评测与发布门槛](./quality/Step_18_双模型评测与发布门槛.md)。
