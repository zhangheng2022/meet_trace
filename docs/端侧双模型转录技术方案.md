# 会迹端侧双模型转录技术方案

> 版本：V0.8
> 状态：Rust 迁移目标基线；当前 C++ 后端保留到双平台硬门槛通过
> 更新日期：2026-07-30

## 1. 目标与边界

会迹使用本地事实 PCM 作为唯一事实源，目标运行时为 Rust 1.88.0、
`whisper-rs` 0.16.0 和其固定的 whisper.cpp 依赖，通过 `flutter_rust_bridge` 2.12.0
与 Cargokit 同时支持 Android 与 iOS 的会中预览和最终转录。录音写入与 VAD/ASR
推理解耦；推理变慢、取消、崩溃或模型不可用时，事实录音必须继续。

应用不依赖 `whisper_ggml` 或 sherpa-onnx。Rust/FRB 只替换原生运行时和桥接，不改变
UI、ViewModel、Domain Port、会议模型锁定、模型分发和最终快照语义。当前
`meettrace_whisper_native` C++/FFI 后端在迁移期保留为 debug 对照；Android+iOS Hard Gate
未全部通过前，不得删除或把 Rust 包装为已正式支持。

## 3. 分层与依赖

```text
View → ViewModel → Use Case / Port → Repository / Service
                                      ├─ WhisperAsrEngineFactory
                                      ├─ WhisperBaseStandardAsrEngine
                                      ├─ WhisperSmallAdvancedAsrEngine
                                      └─ WhisperWorkerFactory
                                           ├─ CppWhisperWorkerFactory（迁移期）
                                           └─ RustWhisperWorkerFactory
                                                ↓
                                      flutter_rust_bridge 2.12.0
                                                ↓
                                           Rust worker
                                       ┌────────┴─────────┐
                              WhisperVadContext   WhisperContext/State
```

- Domain 只定义 `AsrEngine`、模型描述、会议锁定和快照语义。
- UI/ViewModel 不导入 FRB、Rust、FFI 或模型文件细节。
- data/service 层把 Base 与 Small 适配为相同协议；Factory 只按会议锁定的 ID/版本创建。
- `AsrEngine` 领域接口保持不变。FRB 生成代码只放在 data/native 边界，不进入 Domain。
- Rust 工作线程独占 `WhisperContext`、`WhisperState` 和 `WhisperVadContext`；Dart 不持有
  原生指针地址。
- 迁移期 backend 选择只通过依赖注入用于 debug/integration test，不进入用户设置，会议中
  不得热切换。

## 4. 原生构建

Rust/FRB 原生构建仅面向 Android/iOS：

- Rust toolchain 固定 1.88.0；`flutter_rust_bridge` 与 codegen 固定 2.12.0。
- 使用稳定 Cargokit backend，不采用 2.13 beta Native Assets backend。
- `whisper-rs = 0.16.0` 精确固定并提交 `Cargo.lock`。
- 禁止手写 JNI、手工 `jniLibs`、手工复制 `.so` 或为绕过移动平台问题启用私有 C API。
- CPU 为可移植基线，GPU/Metal/Vulkan 初始关闭；平台优化必须经同语料、功耗和温控评测。
- Android Release APK 中每个 `.so` 必须独立验证 16 KB program-header alignment。
- 若 Android/iOS 构建、VAD、取消或释放必须依赖 `whisper-rs raw-api`、私有 fork 或手工原生
  补丁，Hard Gate 1 失败并保留旧 C++ 后端。

## 5. 流式预览与最终转录

录音器固定输出 16 kHz、单声道 PCM16。可靠录音服务先持久化、flush 并更新 checkpoint，
再把副本投递给预览端口。预览 ingress 入队后立即返回，Rust VAD 和 Whisper 均不得运行在
事实写入路径。VAD ingress 或 ASR 队列超限时，只停止/丢弃临时预览并进入仅录音状态。

VAD 初始参数统一为 threshold 0.50、min speech 250 ms、min silence 500 ms、max speech
15 s、speech pad 100 ms、overlap 100 ms。`whisper-rs` 0.16.0 高层 API 以未决 PCM tail
做滚动批检测：每新增 500 ms 重跑尚未提交的 tail，只提交已有足够尾随静音确认的区间，
flush 时处理最后尾段。相同 PCM 使用不同 Dart chunk 大小必须产生完全相同的最终区间。

Engine 单次输入上限为 15 秒。片段时间由 whisper.cpp 时间戳转换为会议全局时间轴，重叠窗口
按既有确定性规则合并。会后始终重新读取完整事实 PCM，以相同 VAD 参数重新识别；成功写完并
校验新快照后才原子激活。Rust 不直接写数据库。AI 总结只能读取激活的最终快照。

## 6. 生命周期与降级

- App 启动准备并校验内置 Base 与公共 Silero VAD。
- Small 通过 HTTPS Range 下载、逐文件大小/SHA-256 校验和原子目录切换安装。
- Small 使用活动版本和使用租约；会议占用期间不得删除或替换。
- `cancel()` 中断 VAD/Whisper 工作并拒绝后续输入；调用幂等。
- `dispose()` 串行等待工作结束后释放 VAD、state 和 context；调用幂等，错误转换为结构化
  `AppFailure`。
- 开始录音后模型锁定。高级模型失败只降级为“仅录音”，不得自动创建 Base Engine。
- VAD 损坏或失败时不开始虚假转录；允许仅录音，最终转录保留修复与重试入口。

旧默认设置只做一次层级迁移：旧标准映射到 Rust Base，旧高级映射到 Rust Small。历史会议
和快照中的旧模型身份是审计事实，不改写。

## 7. 验收

交付至少满足：

1. `flutter analyze`、`flutter test` 通过。
2. Android/iOS 均完成 Rust 库构建、Base/Small/VAD 初始化、识别、取消和 100 次释放循环。
3. Android Release APK 包含 Base + Silero，不包含 Small、sherpa 或 ONNX；全部 `.so`
   通过 16 KB alignment 检查。
4. Android 与 iOS 分别用相同 20 段去敏语料对比旧 C++/新 Rust、Base/Small 的 RTF、
   句后延迟、内存、能耗、温控、静音幻觉和关键事实召回率。
5. 两端各完成 30 分钟事实录音完整性、后台生命周期、取消/释放、最终快照和失败恢复。
6. Rust 关键事实召回不低于旧 C++；纯静音幻觉为 0，噪音幻觉至少下降 80%；句后出字
   P95 ≤ 3 秒；RTF 不恶化超过 10%；峰值 RSS/耗电不恶化超过 15%。
7. iOS arm64 构建和真机证据未完成前，不删除旧 C++，双平台发布状态保持 `blocked`。
