# Meetily 端侧双模型转录技术方案

> 版本：V1.0
> 状态：当前技术基线
> 更新日期：2026-07-24
> 上游需求：[研会 AI Android Alpha PRD V0.5](./研会_AI_Alpha_PRD_无登录版.md)
> 下游计划：[Codex Alpha 开发步骤](./Codex_Alpha_开发步骤.md)

## 1. 目的与现状

本文定义 Android Alpha 的端侧录音、双模型 ASR、最终转录、模型管理和降级架构。

当前仓库已有 Flutter/Forui 应用壳、领域接口、本地事实存储和隔离在 data/service 层的双模型生命周期：标准模型随 APK 准备，高级模型支持空间/网络预检、HTTPS 续传、严格校验、原子激活、租约和安全删除。Step 01 Spike 已验证官方 `sherpa_onnx` 1.13.4 配置、双模型文件、15 秒窗口识别、进程 RSS 和录音连续性；Spike 仍不是正式 `AsrEngine`，录音主链、具体双 Engine 和业务流程须按后续步骤实现并用真机数据校准。

## 2. 不可破坏的约束

1. 本地完整音频是唯一事实源。
2. 音频持久化优先于 ASR 投递。
3. ASR 慢、积压、异常退出或模型损坏时录音继续。
4. 临时转录可丢弃和重建，音频块不可丢失。
5. 最终转录必须从完整音频生成。
6. AI 总结只能读取激活的最终转录快照。
7. 会议开始后模型锁定，不混合两个模型的输出。
8. UI 只依赖 ViewModel/Repository，不直接调用 ONNX、文件系统或 HTTP。

## 3. 模型基线

| 层级 | modelId | 运行时 | 分发 | 目标 |
|---|---|---|---|---|
| 标准 | `sherpa-onnx-paraformer-zh-small-2024-03-09` | sherpa-onnx | APK 内置 | 低功耗、低端设备、普通话/英语 |
| 高级 | `sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25` | sherpa-onnx | 按需下载 | 准确率优先、更多语言能力 |

- 标准模型 INT8 ONNX 文件约 79 MB，发布门槛为模型资源不超过 100 MB（公共运行库除外）。
- 高级模型完整资源约 941 MB，产品预检按至少 2 GB 可用空间执行。
- Step 01 实测标准模型运行必需文件为 81,904,027 字节，高级模型运行必需文件为 987,015,347 字节；双模型发布 Manifest 已按最终文件大小和 SHA-256 固定。
- 具体文件、许可、下载地址和哈希统一进入版本化 Manifest，业务代码不得散落硬编码。
- 方言、多语言、标点、时间戳等能力只在真机和语料验证后写入 `capabilities`。

## 5. 领域模型

### 5.1 模型描述

```dart
enum AsrModelTier { standard, advanced }
enum AsrInstallationType { bundled, downloadable }

final class AsrModelDescriptor {
  AsrModelDescriptor({
    required this.modelId,
    required this.displayName,
    required this.tier,
    required this.version,
    required this.supportedLanguages,
    required this.installationType,
    required this.requiredBytes,
    required this.capabilities,
  });

  final String modelId;
  final String displayName;
  final AsrModelTier tier;
  final String version;
  final List<String> supportedLanguages;
  final AsrInstallationType installationType;
  final int requiredBytes;
  final Set<String> capabilities;
}
```

`AsrModelRegistry` 是已发布模型元数据的单一入口。领域层只使用 `modelId`，不依赖模型文件名。

### 5.2 会议模型归属

```text
requestedModelId       // 用户最初选择
recordingModelId       // 开始前确认的实际模型
recordingModelVersion  // 本场锁定版本
```

若高级模型在开始前不可用，只有用户明确确认后才允许：

```text
requestedModelId = qwen3...
recordingModelId = paraformer...
```

开始录音后 `recordingModelId` 和版本不可变。每个最终快照另外保存实际模型，支持历史音频使用其他已安装模型重新处理。

### 5.3 转录对象

```dart
sealed class TranscriptEvent {
  const TranscriptEvent();
}

final class TranscriptSegmentEvent extends TranscriptEvent {
  const TranscriptSegmentEvent({
    required this.segmentId,
    required this.startMs,
    required this.endMs,
    required this.text,

    required this.isFinalForWindow,
  });
}

final class TranscriptSnapshot {
  // meetingId, actualModelId, actualModelVersion, segments, status, createdAt
}
```

两种模型统一使用 VAD 的全局 `startMs/endMs`。不得把未验证的模型内部时间戳能力当作产品保证。

### 5.4 Step 02 实现边界

- `lib/domain/models/` 已实现不可变的会议、转录、总结、模型描述、模型安装、音频源、状态机和结构化错误对象。
- 会议同时保存请求模型、实际录音模型、版本和显式回退原因；进入录音状态后模型选择锁定。
- 只有 `final + complete + active` 的快照可作为总结输入；激活新最终快照时清除旧摘要引用，失败快照不能改变旧活动快照。
- 会议、录音、处理和模型安装的合法迁移集中在 `workflow_states.dart`，调用方不能通过直接赋值绕过。
- `lib/data/services/asr/asr_engine.dart` 和 `lib/data/repositories/repository_contracts.dart` 只定义纯 Dart 抽象端口，不包含 ONNX、数据库或平台实现。
- `AsrModelDescriptor`、快照片段、总结证据和诊断上下文均做防御性复制，避免外部集合修改领域状态。

## 6. ASR 抽象

```dart
abstract interface class AsrEngine {
  AsrModelDescriptor get descriptor;

  Future<void> initialize();

  Stream<TranscriptEvent> get events;

  Future<void> acceptAudio(
    Float32List samples, {
    required int sampleRate,
    required int startMs,
  });

  Future<TranscriptSnapshot> finalizeMeeting(AudioSource source);

  Future<void> dispose();
}
```

- `ParaformerStandardAsrEngine` 封装标准模型初始化、片段识别和完整音频处理。
- `QwenAdvancedAsrEngine` 封装高级模型初始化、片段识别和完整音频处理。
- `AsrEngineFactory` 根据锁定的模型 ID 和版本组装引擎。
- `AsrCoordinator` 负责队列、状态、生命周期和指标，不包含具体模型分支。
- ViewModel 不得导入以上两个具体 Engine。

## 7. 官方 sherpa_onnx Flutter 包集成

### 7.1 依赖边界

- `pubspec.yaml` 直接依赖官方 `sherpa_onnx` Flutter/Dart 包。
- 依赖版本固定为 Day 1 真机 Spike 验证通过的版本，不使用无上限浮动版本。
- 官方包负责 Dart FFI、Android 原生运行库和 ABI 集成。
- Meetily 不维护 JNI、ffigen、C API 绑定、C/C++ 构建链或私有 ABI 声明，也不把原生库复制到项目 `jniLibs`。
- `ParaformerStandardAsrEngine` 和 `QwenAdvancedAsrEngine` 是 Dart 业务适配器，不包含 `DynamicLibrary.open`、C 指针或 JNI 调用。
- 官方包能力不足时，先验证官方稳定版本和公开 API，再调整依赖版本或目标模型并更新 PRD；不得自建原生桥接。

### 7.2 Dart 适配器职责

- 从 ModelManager 获取已校验的模型目录和版本。
- 将 `AsrModelDescriptor` 转换为官方包公开的识别器配置。
- 通过官方 API 完成初始化、音频输入、结果读取、资源释放和应用级取消。
- 将官方结果转换为统一 `TranscriptEvent` 和 `TranscriptSnapshot`。
- 将第三方异常转换为结构化应用错误，不向 UI 暴露包类型。
- 为单元测试注入 fake adapter；普通单元测试不加载原生运行库。

### 7.3 Android 构建验证

- 原生运行库由官方 Flutter 包及其平台依赖提供，Meetily 只负责验证构建结果。
- Alpha 至少验证 `arm64-v8a`；增加 ABI 前重新计算 APK 体积。
- 构建后检查目标 ABI 是否存在、原生库是否重复、APK 体积和许可证是否符合发布要求。
- APK 必须包含内置标准模型，不得包含按需下载的高级模型文件。
- 依赖升级必须重新执行两个模型的初始化、释放、重复创建和 APK 内容回归。

### 7.4 并发

- 音频写入在独立的高优先级执行链完成。
- 通过官方 Dart API 发起的 ONNX 推理必须调度到不阻塞 UI 和录音写入关键路径的执行链。
- 单场会议同一时刻只允许一个活动 ASR Engine。
- Engine 异常必须转换为结构化错误，不得导致录音 Service 退出。

### 7.5 Step 01 真机校准

- 官方包固定为真机验证过的 `sherpa_onnx` 1.13.4；包与原生运行库版本一致。
- 离线识别不得把 5 分钟完整音频作为一个 utterance 直接输入。Paraformer 上游建议单段输入短于 20 秒；Spike 将统一窗口从 30 秒缩短为 15 秒后，两轮均从 7/10 提升为 20/20 可读。
- 正式 VAD 为两个模型生成相同的全局时间区间，单次识别窗口硬上限为 15 秒；过长语音段须重叠切分并确定性合并。
- Mi 10 上 Paraformer 15 秒窗口首结果为 317～324 ms、RTF 约 0.0214、峰值 RSS 约 455 MiB；正式 Engine 必须逐窗口保留错误/空结果指标并从事实音频支持重试。
- Mi 10 上 Qwen3-ASR 首窗口结果约 18～20 秒、峰值 RSS 约 2.92 GiB，不满足会中“句后准实时”；高级模型必须具备设备能力门槛、积压状态和内存/温控风险提示，不得阻塞录音或自动切换模型。
- 录音连续性探针必须先于高内存模型测试运行；应用架构中录音写入链与 ASR Isolate 始终独立，不能依赖测试顺序保证安全。
- 详细原始指标和限制见 [Step 01 双模型真机 Spike](./quality/Step_01_双模型真机_Spike.md)。

## 8. 音频与 VAD 数据链

### 8.1 事实音频

- 采集格式：16 kHz、单声道、PCM16。
- 音频块先写入临时事实文件，并更新可恢复元数据。
- 结束时 flush、fsync/等价持久化、关闭并原子封存。
- 数据库只在文件状态可验证后标记录音完成。

### 8.2 分发顺序

```text
Microphone chunk
  1. durable writer
  2. update recovery checkpoint
  3. VAD / preview queue
```

第 3 步失败不得回滚前两步。

### 8.3 VAD

- Silero VAD 产生统一、单调递增的音频时间区间。
- VAD 窗口保留少量前后文，具体值由语料评测决定。
- 单次识别窗口硬上限为 15 秒；过长语音段按重叠窗口切分，合并必须确定性去重。
- VAD 结果用于两个模型，确保双模型评测时间边界一致。

### 8.4 有界预览队列

- 队列容量用音频时长而不是只用任务数衡量。
- 达到高水位后停止投递或丢弃最旧的可重建预览任务。
- 不删除事实音频，不把会议标记为失败。
- 暴露 `queuedAudioMs`、`droppedPreviewWindows` 和 `previewLagMs`。
- 队列恢复后可以从当前时间继续预览，无需补齐所有旧预览。

## 9. 临时与最终转录

### 9.1 会中临时转录

- 目标是“句后准实时”，不是逐字流式字幕。
- 每个 VAD 片段带稳定 ID 和全局时间区间。
- UI 按 `startMs`、序号进行确定性排序。
- 同一窗口的修订替换旧临时文本，不产生无界重复记录。
- Engine 失败后状态转为“仅录音/转录暂停”，不切换模型。

### 9.2 会后最终转录

1. 确认事实音频已封存。
2. 创建 `processing` 快照记录。
3. 从完整音频顺序读取并按锁定模型推理。
4. 合并、排序、校验时间区间。
5. 在事务中写入完整快照。
6. 成功后原子切换 `activeTranscriptSnapshotId`。
7. 失败时保留旧快照和音频。

重新转录时可选择另一个已安装模型，但必须生成新快照，并记录 `actualModelId/actualModelVersion`。不得将不同模型的片段拼入同一快照。

## 10. 模型生命周期

### 10.1 Manifest

Manifest v1 顶层包含 `schemaVersion`、`minAppVersion` 和 `models`。每个模型必须包含：

- 与 `AsrModelRegistry` 完全一致的 `modelId`、`version`、`tier`、`installationType` 和 `requiredBytes`。
- 非空且路径不重复的 `files`；每项包含安全相对 `path`、正整数 `bytes`、64 位小写十六进制 `sha256` 和 `url`。
- 非空 `license.name` 以及指向仓库内声明文件的安全相对 `license.noticePath`。

可下载模型只接受 HTTPS URL，内置模型只接受 `asset://` URL。逐文件字节数之和必须等于 `requiredBytes`；客户端拒绝未知 schema、最低 App 版本过高、重复模型 ID、路径穿越、占位符以及任何与 Registry 分叉的字段。

`ModelFileVerifier` 对准备目录执行严格文件集、字节数和 SHA-256 校验，多余文件同样视为失败。双模型发布 Manifest 位于 `assets/models/manifest.json`：标准模型使用最终打包资产，高级模型六个文件使用固定 revision 的 HTTPS URL、真实文件哈希和许可 NOTICE，不含占位条目。

### 10.2 内置标准模型

1. 标准模型随 APK 进入只读 assets。
2. 首次启动或首次转录前复制到私有临时目录。
3. 逐文件校验大小和 SHA-256。
4. 原子重命名为版本目录。
5. 更新 `ModelInstallation`。
6. 标准模型不能由用户删除。

若 assets 读取、空间或校验失败，系统进入仅录音模式并保留错误码。

当前实现由 `FlutterModelAssetSource` 将 `asset://` URL 映射为 Flutter asset key，`BundledModelPreparationService` 负责以下顺序：

```text
检查现有版本
  → 清理目标版本临时目录
  → 逐文件读取 asset、写入和 flush
  → 严格校验文件集、字节数、SHA-256
  → 原子重命名为版本目录
  → 保存 ModelInstallation(installed)
```

数据库保存失败时不回滚已通过校验的最终目录；下次准备先重新校验并收养该目录。校验失败只保存 `failed`，不形成最终目录或 `installed`。已正确安装时不重复读取 asset。

`model.int8.onnx` 与 `tokens.txt` 合计 `81,904,027` 字节，已注册为显式 Flutter assets，并由真实资产测试核对发布 Manifest 的大小、SHA-256 和严格文件集。精确上游 `crazyant/speech_paraformer_asr_nat-zh-cn-16k-common-vocab8358-onnx` 的 ModelScope API 仍未声明 `License`、`LicenseName` 和 `LicenseLink`；产品负责人已明确批准将权重用于 Android Alpha APK，来源、归档哈希和未决许可状态记录在 `assets/licenses/paraformer-small-NOTICE.txt`。公开分发前仍须完成再分发许可确认。

### 10.3 高级模型按需下载

状态机：

```text
notInstalled
  → checking
  → downloading
  → verifying
  → installed

downloading ↔ paused
任意活动状态 → failed → retry
installed → updateAvailable → downloading(new version)
installed → deleting → notInstalled
```

- 下载前通过 `storage_space` 检查至少 2 GiB 空间，通过 `connectivity_plus` 区分无网络、非计费网络和需用户确认的移动/未知网络；连接类型只用于提示，真实网络错误仍由 HTTP 层处理。
- `HttpModelFileDownloader` 使用 `dart:io HttpClient` 和 HTTPS，按文件写入版本化临时目录；服务器支持 Range 时从已有字节续传。
- 取消保留可续传临时文件并记录 `paused`；网络失败记录可重试错误；哈希失败删除错误临时版本，均不触碰旧活动版本。
- 全部六个文件通过严格文件集、大小和 SHA-256 校验后，临时目录原子重命名为版本目录，再由 SQLite 单事务切换 `active_model_versions`。
- 正在录音或处理的版本持有带过期时间的 `model_usage_leases`；有效租约释放前不删除，崩溃遗留租约到期后可清理。
- 删除只清理目标版本临时/最终目录、安装记录和匹配活动指针；会议、转录和总结表不依赖安装记录，因此历史内容保持。

### 10.4 版本兼容

- 标准模型版本随 App 发布。
- 高级模型由远端 Manifest 更新，但客户端必须校验 `schemaVersion` 和最低 App 版本。
- 历史会议保存实际版本，不依赖当前默认版本反推。
- 模型删除只删除模型文件，不删除历史会议和转录。

## 11. 状态、错误与降级

统一错误至少包含：

```text
code
stage
modelId?
modelVersion?
recoverability
userAction
diagnosticContext
```

| 故障 | 行为 |
|---|---|
| 标准模型缺失/损坏 | 仅录音；提示修复或重装 |
| 高级模型下载失败 | 保留旧版本；可重试或改用标准模型 |
| 高级模型校验失败 | 删除临时版本；不覆盖已安装版本 |
| 开始前高级模型初始化失败 | 由用户确认改用标准模型或取消 |
| 录音中 Engine 失败 | 录音继续；临时转录停止；不自动切换 |
| 预览队列积压 | 丢弃可重建预览；记录指标 |
| 最终转录失败 | 保留音频和旧快照；允许重试或完整重转 |
| 说话人分离失败 | 使用未分离最终转录继续 |
| 总结失败 | 最终转录保持可用；单独重试总结 |

所有回退必须在数据和 UI 中可见，不能静默更换模型。

## 12. 本地存储和事务

正式选型使用 `sqflite` 2.4.3 保存会议、模型安装、全局设置、快照、片段、摘要和任务状态，文件系统保存音频和模型。Android 使用 `sqflite` 平台实现；普通单元测试使用 `sqflite_common_ffi` 2.3.7 与 `sqlite3` 2.9.4 的内存数据库，避免测试依赖模拟器或运行时下载原生库。App 私有根目录由 `path_provider` 2.1.6 提供。

### 12.1 SQLite v1 基础、v2 设置与 v3 模型生命周期

数据库文件为 `<application-support>/meetily/database/meetily.db`，打开时强制启用外键。v1 建立：

- `meetings`
- `transcript_snapshots`
- `transcript_segments`
- `summaries`
- `summary_items`
- `summary_evidence`
- `model_installations`
- `processing_tasks`

v2 增加 `app_settings`，以 `default_asr_model_id` 保存全局默认模型；没有记录时由 Registry 返回标准模型初始值，保存前必须确认模型 ID 已注册。

v3 增加 `active_model_versions` 和 `model_usage_leases`。安装记录与活动版本在同一事务中写入；租约记录 `owner_id`、获取时间和过期时间，外键只关联对应模型版本。

v1→v3 迁移依次新增设置和模型生命周期表并保留现有数据。会议删除通过外键只级联对应快照、片段、总结和处理任务。Repository 使用 update/insert，不使用会先删除旧行的 `INSERT OR REPLACE`，避免意外触发级联删除。最终快照写入和 `activeTranscriptSnapshotId` 切换在同一事务中，并用旧活动快照 ID 做并发检查。

### 12.2 App 私有文件布局

```text
<application-support>/meetily/
  database/meetily.db
  meetings/<meetingId>/audio/
    recording.pcm.tmp
    fact.pcm
  models/
    .tmp/<modelId>/<version>/
    <modelId>/<version>/
```

ID 只能作为安全的单一路径片段，禁止 `..`、斜杠、反斜杠和空字节。

### 12.3 耐久提交

关键提交顺序：

```text
write temp file
  → verify/flush
  → atomic rename
  → database transaction references final path
```

临时文件必须存在、非空并完成 flush；原子重命名后再次核对最终文件，再执行数据库引用事务。数据库事务失败时最终文件作为可恢复孤儿保留，绝不写入指向不存在文件的引用。

### 12.4 启动恢复

启动恢复器扫描：

- `recording` 且进程已不存在的会议：存在临时/最终事实音频时封存并进入 `processing`，文件缺失或为空时记录结构化失败。
- `running` 且租约过期的处理任务：清除租约并重新进入 `queued`。
- `models/.tmp` 下未完成的模型版本目录：只在校验目标仍位于临时根目录后递归清理。
- 已完成但未激活的最终转录快照：激活每场会议最新快照，并清除旧摘要引用。

恢复操作必须幂等；相同残留第二次扫描的变更数必须为 0。

依赖依据：[sqflite](https://pub.dev/packages/sqflite)、[sqflite_common_ffi](https://pub.dev/packages/sqflite_common_ffi)、[path_provider](https://pub.dev/packages/path_provider)。

## 13. AI 总结边界

- `GenerateSummaryUseCase` 只接收 `final + active + complete` 的快照。
- 本地模型总结可后续扩展，不在双 ASR 模型范围内。
- 云端总结只发送最终文本、片段 ID 和最小提示信息。
- 无安全网关时功能关闭，禁止将永久 API 密钥写入 App。
- 返回结构先做 schema 校验，再做证据片段存在性和时间区间校验。
- 无有效证据的结论标记“待核对”。

## 14. 测试策略

### 14.1 单元测试

- Registry/Manifest 解析、大小和 SHA-256 校验。
- `AsrEngineFactory` 的模型选择。
- 会议模型锁定和显式回退记录。
- 有界队列的高水位和丢弃策略。
- 片段排序、重叠合并和全局时间轴。
- 最终快照原子切换与失败保留。
- 模型版本租约和更新回滚。
- 摘要只读取激活最终快照。

### 14.2 组件测试

- Forui 应用壳中的加载、空白、错误和降级状态。
- 设置页模型状态全覆盖。
- 开始会议页继承默认与本场覆盖。
- 未安装高级模型的下载/改用标准模型流程。
- 录音中无模型切换入口。
- 证据跳转和摘要过期提示。

### 14.3 真机集成测试

两模型分别执行：

- 初始化和 5 分钟冒烟。
- 30 分钟连续录音和转录。
- 断网、锁屏、后台和 App 强制终止恢复。
- ASR 人为降速和故障注入。
- 完整音频最终转录和重新转录。
- 证据区间播放。

### 14.4 双模型对比评测

使用相同 20 段真实会议音频，保存原始记录：

- RTF P50/P95。
- 句后出字 P50/P95。
- 峰值内存。
- 30 分钟耗电和温控状态。
- 字错误率/人工错误统计。
- 人名、数字、产品名、结论和行动项的关键事实召回率。
- 最终转录耗时。

标准模型必须满足 PRD 的体积、性能、能耗和关键事实门槛。高级模型结果用于明确设备支持级别和产品提示，不得只保留“通过/失败”结论。

## 15. 可观测性

允许记录：

- 会议匿名 ID、阶段、模型 ID/版本。
- 音频时长、队列深度、预览丢弃数。
- 初始化、RTF、延迟、内存、耗电和温控。
- 结构化错误码和恢复结果。

禁止记录：

- 原始音频。
- 完整转录和摘要正文。
- 下载凭证、服务密钥或用户可识别内容。

诊断导出由用户主动触发。
