# 会迹端侧双模型转录技术方案

> 版本：V0.7
> 状态：当前技术基线
> 更新日期：2026-07-30

## 1. 目标与边界

会迹使用本地事实 PCM 作为唯一事实源，以官方 `ggml-org/whisper.cpp` v1.9.1 同时提供
Android 与 iOS 的端侧会中预览和最终转录。录音写入与 ASR 推理解耦；推理变慢、取消、
崩溃或模型不可用时，事实录音必须继续。

应用不依赖 `whisper_ggml` 或 sherpa-onnx。直接接入官方源码的目的，是固定上游版本、
控制 ABI 和资源释放，同时保持 Flutter 业务层只依赖统一 `AsrEngine`。

## 3. 分层与依赖

```text
View → ViewModel → Use Case / Port → Repository / Service
                                      ├─ WhisperAsrEngineFactory
                                      ├─ WhisperBaseStandardAsrEngine
                                      ├─ WhisperSmallAdvancedAsrEngine
                                      └─ WhisperAdapter → isolate
                                                           ↓
                                              meettrace_whisper_native
                                                           ↓
                                                C ABI → whisper.cpp
```

- Domain 只定义 `AsrEngine`、模型描述、会议锁定和快照语义。
- UI/ViewModel 不导入 FFI、Native Assets 或模型文件细节。
- data/service 层把 Base 与 Small 适配为相同协议；Factory 只按会议锁定的 ID/版本创建。
- `meettrace_whisper_native` 是隔离的本地 package。C ABI 只暴露上下文创建、转录、分段读取、
  取消、错误和销毁；Dart 绑定由 `ffigen` 生成。

## 4. 原生构建

Native Assets hook 仅为 Android/iOS 构建：

- C 源码先以 C11 编译成静态库。
- C++ 源码和最小包装以 C++17 编译并链接为 `libmeettrace_whisper`。
- Android 静态链接 libc++，不使用 JNI 或手工 `jniLibs`。
- CPU 为可移植基线，GPU 关闭；平台优化必须经过相同语料、功耗和温控评测后另行批准。
- `@Native` 绑定使用 package asset ID，不在应用代码中调用 `DynamicLibrary.open`。

## 5. 流式预览与最终转录

录音器固定输出 16 kHz、单声道 PCM16。可靠录音服务先持久化并更新 checkpoint，再把副本
投递给预览端口。连续切窗器生成 2 秒窗口和 0.5 秒重叠；队列按音频时长设上限，积压时只丢弃
最旧的临时预览任务。`WhisperAdapter` 在专用 isolate 持有模型上下文，并以
`TransferableTypedData` 接收 Float32 PCM。

Engine 单次输入上限为 15 秒。片段时间由 `whisper.cpp` 时间戳转换为会议全局时间轴；
重叠窗口按既有确定性修订规则合并。会后始终重新读取完整事实 PCM 分窗转录，成功写完新快照
后才原子激活。AI 总结只能读取激活的最终快照。

## 6. 生命周期与降级

- App 启动准备并校验内置 Base。
- Small 通过 HTTPS Range 下载、逐文件大小/SHA-256 校验和原子目录切换安装。
- Small 使用活动版本和使用租约；会议占用期间不得删除或替换。
- `cancel()` 通过原生 atomic abort callback 中断正在执行的 `whisper_full`。
- `dispose()` 串行等待工作结束后释放上下文；错误转换为结构化 `AppFailure`。
- 开始录音后模型锁定。高级模型失败只降级为“仅录音”，不得自动创建 Base Engine。

旧默认设置只做一次层级迁移：旧标准映射到 Base，旧高级映射到 Small。历史会议和快照中的
旧模型身份是审计事实，不改写。

## 7. 验收

交付至少满足：

1. `flutter analyze`、`flutter test` 通过。
2. Android Debug APK 构建通过，包含目标 ABI 的 `libmeettrace_whisper.so`、Base 权重，
   不包含 sherpa、ONNX、Silero 或 Small 权重。
3. Android 与 iOS 分别用相同 20 段去敏语料对比 Base/Small 的 RTF、句后延迟、内存、
   能耗、温控和关键事实召回率。
4. 两端各完成 30 分钟事实录音完整性、后台生命周期、取消/释放、最终快照和失败恢复。
5. iOS arm64 构建和真机证据未完成前，双平台发布状态保持 `blocked`。
