# 研会 AI

> Android 线下会议实时转录与 AI 总结｜两周封闭 Alpha 产品需求文档

| 项目 | 内容 |
|---|---|
| 版本 | V0.4（无登录、Qwen3-ASR 离线转录版） |
| 状态 | 范围已确认，可进入技术可行性检查与开发 |
| 目标平台 | Android；首轮只覆盖指定测试机型 |
| 开发周期 | 2 周 |
| 团队假设 | 2 名工程师 + 1 名兼职产品/设计 |
| 试用规模 | 5–10 名用户，至少 20 场真实线下会议 |

## 0. 产品决策

**本地录音是唯一事实源；Qwen3-ASR 在手机端生成句级近实时文本；会议结束后基于完整音频生成最终转录，再生成统一结构的 AI 总结。**

技术选型固定为 `Qwen3-ASR-0.6B INT8 + sherpa-onnx`。这里的“实时”是由 VAD 分句驱动的端侧近实时结果，不是逐字流式字幕；详细边界与验收方法见 [Qwen3-ASR 离线转录技术方案](./Qwen3-ASR离线转录技术方案.md)。

本版本不设置账号体系。用户安装 App 后直接进入本机会议列表：

- 无需注册或登录；
- 不提供用户资料；
- 不提供多端同步；
- 不提供换机恢复；
- 不提供团队空间和成员权限；
- 会议列表、最终转录、AI 总结和编辑结果以本地保存为主；
- 音频和转录默认只在本机处理；云端只承担 AI 总结，不作为用户历史数据中心。

## 2. 产品定义

### 2.1 用户问题

线下面对面会议中，参会者需要同时倾听、表达和记录。手工笔记容易遗漏上下文，完整录音又难以回看；会议结束后整理逐字稿、结论和行动项通常需要额外投入。

研会 AI 使用安卓手机完成稳定录音，在会中提供实时文字，在会后生成经过完整音频校正的最终转录与结构化总结，让用户能够快速回顾、核验、编辑和分享。

### 2.2 核心假设

1. 用户愿意在普通线下会议中，将安卓手机放在桌面中央持续录音。
2. 句级近实时文字可以降低遗漏感，用户接受它不是逐字字幕，且在设备负载较高时允许延迟。
3. 用户更关心会后转录和总结是否可靠、可核验，而不是摘要文风是否华丽。
4. 说话人分离、证据跳转和可编辑能力可以提升用户对 AI 总结的信任。
5. 无账号模式可以降低首次使用成本，帮助两周 Alpha 更快验证核心价值。
6. 使用 sherpa-onnx 已支持的 Qwen3-ASR 0.6B INT8 与成熟的大模型服务，可以在两周内完成可测试闭环。

### 2.3 产品原则

| 原则 | 产品含义 | 实现约束 |
|---|---|---|
| 录音优先 | 转录故障不能中断本地录音 | 音频增量落盘，录音与端侧推理解耦 |
| 临时与最终分离 | 会中字幕允许变化，会后文本才是最终版本 | 界面明确标记状态，总结只使用最终转录 |
| 本地优先 | 用户历史不依赖账号和云端工作区 | 会议列表、转录、总结和编辑结果保存在设备 |
| 最少上传 | 音频和转录默认留在本机 | AI 总结只上传最终文本，处理完成后按策略清理 |
| 结论可核验 | 关键总结必须能够回到原文和录音 | 每条关键内容绑定转录片段及时间戳 |
| AI 不补事实 | 缺失的负责人、时间或结论必须留空 | 使用结构约束、证据校验和编辑流程 |
| Alpha 先验证 | 先证明核心价值和链路可靠性，再扩展产品形态 | 不建设账号、团队、项目和生态集成 |

## 3. 目标与边界

### 3.1 两周目标

1. 完成一条在真实安卓设备上可连续使用的端到端会议记录链路。
2. 验证端侧句级近实时转录和会后最终转录可以共存，并在高负载时正确降级和恢复。
3. 验证统一 AI 总结对通用会议是否足够有用、可信且容易修正。
4. 验证无账号、本地优先模式能否降低用户开始记录会议的阻力。
5. 收集真实用户对录音意愿、总结使用率、修改量和失败原因的数据。

### 3.2 非目标

- 不建设注册、登录、验证码、用户资料或账号找回能力。
- 不提供跨设备同步、换机恢复和云端历史会议列表。
- 不追求公开发布、应用商店上架或大规模设备兼容。
- 不支持 iOS、平板、桌面端或 Web 端录音。
- 不接入腾讯会议、飞书、钉钉、Zoom 等线上会议系统。
- 不录制手机系统内部音频。
- 不建设团队空间、成员权限、项目管理、协同编辑或独立待办系统。
- 不做声纹注册和真实姓名自动识别。
- 不做端侧 AI 总结、Qwen3-ASR 1.7B 部署、私有化服务或第三方业务系统集成。
- 不承诺超过 30 分钟会议的稳定性；更长会议可试用，但不作为 Alpha 验收条件。

### 3.3 发布范围

| 层级 | 进入 Alpha | 后移 |
|---|---|---|
| 使用入口 | 安装后直接进入本机会议列表 | 登录、注册、用户中心 |
| 平台 | Android、指定测试机型、封闭安装包 | iOS、应用商店、多端产品 |
| 采集 | 麦克风录音、增量本地保存、30 分钟稳定性 | 系统音频、复杂外接设备适配 |
| 转录 | 实时临时文本、会后最终文本、说话人分离与重命名 | 声纹身份、实时翻译、专业词库管理 |
| AI | 统一五段式总结、证据绑定、编辑和确认 | 多种会议模板、问答、跨会议知识库 |
| 输出 | Android 系统分享纯文本或 Markdown | 公开分享链接、PDF、多人评论、外部集成 |
| 数据 | 本地会议历史、云端临时总结 | 云端历史、同步、换机恢复 |

## 4. 核心用户闭环

1. 用户打开 App，直接进入本机会议列表。
2. 用户点击“开始新会议”。
3. App 展示本地录音、端侧转录及 AI 总结处理说明，提示用户确认已取得参会者同意。
4. 用户授予麦克风权限，可选填会议标题并开始会议。
5. App 立即将音频增量写入本地，同时通过 VAD 和 Qwen3-ASR 在端侧生成句级临时文本。
6. 用户在会中查看带有“临时”标识的句级近实时文字。
7. 设备负载较高时实时文字允许延迟，但本地录音继续。
8. 用户结束会议后，App 封存本地音频。
9. App 基于完整音频在本机生成最终转录；说话人分离作为可降级的会后步骤。
10. App 只将最终转录提交给 AI 总结服务。
11. AI 总结和证据关系保存到本机，音频无需上传。
12. 用户可以重命名说话人、跳回原文、播放对应录音并修改总结。
13. 用户通过 Android 系统分享面板导出结果，或删除整场会议。

> **失败边界：**实时转录失败不等于会议失败。只有本地录音无法持续写入，或最终音频无法恢复，才判定本场会议记录失败。

## 5. 状态模型

| 对象 | 状态 | 用户看到什么 | 系统规则 |
|---|---|---|---|
| 会议 | 录音中 | 计时、录音正常标识、实时文字区域 | 持续本地落盘，音频同时进入端侧 VAD |
| 实时转录 | 正常 | 临时文字持续出现 | 只用于会中阅读，不触发最终总结 |
| 实时转录 | 已降级 | “实时文字稍有延迟，录音仍在继续” | 暂停解码或限制队列，录音继续落盘 |
| 会议 | 处理中 | 最终转录、说话人整理、AI 总结的分阶段进度 | 任一处理阶段可重试，本地音频不得丢失 |
| 最终转录 | 可用 | 稳定文本、说话人编号和时间戳 | 覆盖临时文本，后续总结只使用此版本 |
| AI 总结 | 待确认 | 五段式结果和证据入口 | 允许编辑和删除，不自动标记为已确认 |
| 会议 | 已完成 | 本机保存的转录、总结和分享入口 | 云端总结临时数据进入清理流程 |
| 会议 | 处理失败 | 失败阶段、重试入口和录音安全说明 | 允许重新转录或重新总结 |

## 6. P0 功能需求

### FR-001 本机会议列表

**产品行为**

- App 启动后直接进入会议列表，不出现登录或注册页面。
- 会议按时间倒序展示。
- 每条会议展示标题、日期、时长和处理状态。
- 会议列表、编辑结果和处理状态保存在本机。
- 标题为空时，使用开始时间生成默认标题。

**通过条件**

- 新安装 App 可以直接开始第一场会议。
- 退出并重新打开 App 后，会议列表和处理状态仍然存在。
- 设备中不同会议的数据不会相互覆盖。

### FR-002 开始会议

**产品行为**

- 用户可以输入可选会议标题。
- 首次录音前展示数据处理和参会者同意提示。
- App 请求麦克风权限。
- 权限被拒绝时，明确说明原因并提供再次授权入口。
- 不要求用户填写姓名、手机号、邮箱或其他身份信息。

**通过条件**

- 从会议列表到开始录音不超过 3 个主要操作。
- 未获得麦克风权限时不能进入录音状态。
- 整个开始流程不存在登录、注册或身份资料步骤。

### FR-010 本地增量录音

**产品行为**

- 开始会议后立即采集麦克风音频。
- 音频以可恢复方式持续写入 App 私有目录。
- 录音链路不依赖网络、实时转录或 AI 服务。
- 录音页持续显示计时、录音状态、剩余空间预警和结束入口。
- Alpha 可以要求 App 保持前台；未经测试不得宣称支持后台或锁屏录音。

**通过条件**

- 指定测试机型连续录制 30 分钟不崩溃，且音频可完整播放。
- App 异常终止后，重新打开能够发现未完成会议。
- 存储空间不足时提前提示，并安全封存已有音频。

### FR-011 实时临时转录

**产品行为**

- 录音期间通过 VAD 分句，并使用 Qwen3-ASR 0.6B INT8 在本机展示近实时文字。
- 实时文字明确标记为“临时转录”。
- 语音段封闭至文字出现的延迟 P95 不超过 3 秒。
- 会中以完整语句为单位更新，不模拟逐字流式输出。
- 临时文本不作为分享和 AI 总结的最终来源。

**通过条件**

- 实时文字按时间顺序出现，用户可以在会中滚动查看。
- 指定目标设备上达到句后出字目标。
- 端侧推理失败或积压时，本地录音继续，页面不误报整场会议失败。

### FR-012 端侧负载降级与断网

**产品行为**

- 网络断开不影响录音、句级转录或会后最终转录。
- 推理队列积压时显示“实时文字稍有延迟，录音仍在继续”。
- 队列积压不得占用录音写盘线程，也不得丢弃本地音频。
- AI 总结需要网络；断网时保留最终转录并允许稍后重试。

**通过条件**

- 模拟断网 3 分钟，本地录音和端侧转录保持可用。
- 网络恢复后能够继续生成 AI 总结。
- 最终转录覆盖整场本地音频。
- 用户始终能够区分录音状态和转录状态。

### FR-020 结束会议与会后处理

**产品行为**

- 用户结束会议后，系统先封存本地音频。
- 处理页按顺序展示“本地最终转录 → 说话人整理（可选）→ AI 总结”。
- 最终转录必须基于完整音频重新生成。
- 各处理阶段可以独立重试。
- 重新生成总结不要求重新转录。
- 处理完成后，最终结果写入本机会议数据。

**通过条件**

- 30 分钟会议结束后 5 分钟内产出最终转录和 AI 总结。
- 处理失败时显示失败阶段和可执行的重试入口。
- AI 总结服务失败不影响用户访问本地录音和最终转录。

### FR-021 说话人分离与重命名

**产品行为**

- 最终转录按发言段显示“发言人 1 / 2 / 3”等编号。
- 用户可以将同一编号批量重命名。
- 重命名结果同步更新全文和总结展示。
- 系统不注册声纹、不推断真实姓名，也不跨会议记住身份。

**通过条件**

- 至少两人会议可以产生可区分的发言段。
- 一次重命名可以更新该发言人在整场会议中的全部标签。

### FR-030 统一五段式 AI 总结

**产品行为**

所有会议使用同一输出结构：

1. 会议概述；
2. 核心讨论；
3. 已确认结论；
4. 行动项；
5. 未决问题。

行动项字段包括：

- 事项；
- 负责人；
- 截止时间。

原文未明确负责人或截止时间时，对应字段保持为空。

**通过条件**

- 五个区块始终存在。
- 无内容时显示“未识别到”，不得编造内容填充。
- 同一次输入重复生成时，字段结构保持稳定。
- 总结只使用最终转录。

### FR-031 证据绑定与事实约束

**产品行为**

- 核心讨论、结论、行动项和未决问题中的每一条内容至少绑定一个转录片段和时间戳。
- 模型不得补全原文未出现的人名、日期、数字或承诺。
- 不同发言相互矛盾且未形成结论时，应归入“未决问题”。

**通过条件**

- 点击关键总结项可以定位到对应转录片段。
- 抽检中不存在无法追溯到原文的关键结论。
- 负责人和截止时间不明确时保持空值。

### FR-032 编辑、确认与重新生成

**产品行为**

- 用户可以修改或删除任意总结条目。
- 用户可以重新生成整份总结。
- 系统区分“AI 生成”和“用户已确认”状态。
- 重新生成前提醒可能覆盖未保存的编辑。
- 所有编辑结果保存在本机。

**通过条件**

- 编辑后退出再进入，修改内容仍然存在。
- 删除总结条目不会删除原始转录。
- 用户能够明确判断当前结果是否已经确认。

### FR-040 原文与录音核验

**产品行为**

- 转录段显示时间戳和说话人标签。
- 点击总结证据可以跳到对应转录。
- 点击转录片段可以从对应时间播放本地录音。
- 音频播放与文字高亮保持基本同步。

**通过条件**

- 从关键总结项到对应录音不超过 2 个操作。
- 音频定位误差不超过 3 秒。

### FR-041 系统分享

**产品行为**

- 通过 Android 系统分享面板导出纯文本或 Markdown。
- 默认包含标题、时间和五段式总结。
- 用户可以选择附加完整转录。
- Alpha 不生成公开网页链接，不处理多人访问权限。

**通过条件**

- 结果可以成功分享到至少一种测试应用。
- 分享内容不包含内部 ID、模型提示词、设备标识或调试信息。

### FR-042 删除会议

**产品行为**

- 用户可以删除单场会议。
- 删除前明确提示将清除本地录音、转录、总结和编辑结果。
- 若该会议仍有 AI 总结临时任务，App 同时发送清理请求。
- 用户可以在设置中执行“清除全部会议数据”。

**通过条件**

- 删除后会议不再出现在本机列表中。
- 本地录音和结果无法继续访问。
- AI 总结任务清理失败时显示待重试状态。

## 7. 页面与关键交互

| 页面 | 主要内容 | 必须处理的状态 |
|---|---|---|
| 会议列表 | 新建入口、会议标题、时间、时长、处理状态 | 空列表、处理中、失败、已完成 |
| 开始会议 | 可选标题、录音同意说明、麦克风权限 | 首次授权、拒绝、存储不足 |
| 录音页 | 计时、录音状态、临时转录、端侧负载、结束 | 正常、转录延迟、转录失败、录音故障 |
| 处理页 | 最终转录、说话人整理、AI 总结三段进度 | 进行中、部分失败、重试、完成 |
| 结果页 | 五段式总结、最终转录、说话人重命名、证据和播放 | 待确认、已编辑、已确认、重新生成 |
| 分享与删除 | 系统分享选项、是否附原文、删除确认 | 分享失败、总结任务清理待重试 |
| 本地设置 | 音频保留、清除全部数据、隐私说明、版本信息 | 清理中、清理失败、无数据 |

### 7.1 录音页信息优先级

1. **录音是否仍在进行：**持续显示录音标识和计时。
2. **本地文件是否安全：**写入故障必须给出不可忽略的错误。
3. **端侧转录是否正常：**推理延迟提示不能覆盖或混淆录音状态。
4. **临时文字内容：**允许延迟、修订和滚动查看。

### 7.2 处理页进度规则

- 进度按“本地最终转录 → 说话人整理（可选）→ AI 总结”展示。
- 不使用无法解释的单一百分比。
- 用户可以离开处理页，会议列表持续显示处理状态。
- 最终转录完成但总结失败时，用户仍可查看和分享转录。
- 本地最终转录尚未完成前不得自动清理原始音频。

## 8. AI 输出契约

| 区块 | 输出要求 | 证据规则 |
|---|---|---|
| 会议概述 | 用 1–3 句话说明主题、目的和总体结果；无法判断目的时只描述主题 | 至少绑定一个代表性片段 |
| 核心讨论 | 按主题列出主要观点和分歧，不把观点写成已确认结论 | 每条至少绑定一个片段，分歧可以绑定多个片段 |
| 已确认结论 | 只记录明确达成或由主持人确认的结论 | 每条必须绑定形成结论的原文 |
| 行动项 | 输出事项、负责人和截止时间，未知字段为空 | 每条必须绑定提出或确认任务的片段 |
| 未决问题 | 记录未回答问题、待确认信息和未形成一致的分歧 | 每条绑定问题或分歧片段 |

### 8.1 AI 禁止行为

- 不得把建议、猜测、反问或个人观点自动升级为团队结论。
- 不得补写原文不存在的负责人、日期、数字、原因或下一步。
- 不得以常识替代会议内容。
- 不得把模型自身知识混入会议事实。
- 不得生成没有证据时间戳的关键条目。
- 不得在转录仍为临时状态时生成最终总结。

### 8.2 质量评审方法

每场会议由用户选择：

- 无需修改；
- 轻微修改；
- 大幅修改；
- 不可用。

同时记录修改原因：

- 事实错误；
- 遗漏；
- 错误结论；
- 行动项字段错误；
- 重复；
- 表达问题。

Alpha 以“无需修改 + 轻微修改”达到 70% 为可用门槛。关键内容证据可追溯率必须达到 100%。

## 9. 无登录数据模型

### 9.1 本机身份

- App 首次启动时生成随机安装标识。
- 安装标识不包含姓名、手机号、邮箱、设备序列号等直接身份信息。
- AI 总结请求使用安装范围内的随机凭证进行临时任务隔离。
- 凭证保存在 Android 安全存储中，不向用户展示。
- 卸载 App 后不提供历史恢复。

安装标识只用于：

- 区分不同设备提交的 AI 总结任务；
- 查询当前设备发起的总结状态；
- 删除当前设备对应的临时总结数据；
- 防止不同测试设备互相读取总结结果。

安装标识不得用于：

- 建立用户画像；
- 跨设备识别同一自然人；
- 广告跟踪；
- 联系人匹配；
- 团队成员识别。

### 9.2 本地数据

本地保存：

- 会议标题和时间；
- 会议处理状态；
- 原始录音；
- 最终转录；
- 说话人重命名结果；
- AI 总结；
- 用户编辑和确认结果；
- 分享选项偏好。

### 9.3 AI 总结临时数据

云端只用于：

- 接收最终转录文本；
- 生成结构化 AI 总结；
- 返回总结结果。

原始音频、Qwen3-ASR 模型、临时转录、最终转录数据库、说话人分离和证据时间映射均在本机处理。

云端不提供：

- 历史会议列表；
- 用户资料；
- 多端同步；
- 换机恢复；
- 团队共享空间。

## 10. 数据、隐私与保留

| 数据 | 保留规则 |
|---|---|
| 本地录音 | 默认保留 7 天；用户可以提前删除或修改保留设置 |

- 分享内容不得包含安装标识、访问凭证或内部任务 ID。
- 用户应在卸载前使用“清除全部数据”，App 设置页需明确提示无账号模式无法在卸载后恢复或远程删除历史。
- Alpha 不替代用户履行当地法律和组织内部的录音合规义务。

## 12. Alpha 指标与实验设计

### 12.1 核心指标

| 指标 | 目标 | 计算口径 |
|---|---:|---|
| 全链路完成率 | ≥ 90% | 成功获得本地录音、最终转录和 AI 总结的会议数 ÷ 已结束会议数 |
| 录音完整率 | 100% | 抽检音频覆盖预期时长且不存在不可恢复缺口 |
| 句后出字延迟 P95 | ≤ 3 秒 | VAD 封闭语音段到临时文字出现的延迟 |
| 会后处理时长 | ≤ 5 分钟 | 30 分钟会议从结束到最终转录和总结均可用 |
| 总结可用率 | ≥ 70% | “无需修改”或“轻微修改”的总结占比 |
| 关键项可追溯率 | 100% | 带证据的结论、行动项和未决问题占全部关键项的比例 |
| 首次使用完成率 | ≥ 80% | 安装后成功完成第一场会议的用户占比 |
| 再次使用意愿 | ≥ 50% | 愿意继续记录下一场会议的测试用户占比 |

### 12.2 试用设计

1. 招募 5–10 名 Android 用户，覆盖至少 3 种手机型号和不同会议主题。
2. 每名用户完成 2–4 场线下会议，总计至少 20 场。
3. 目标会议时长为 10–30 分钟。
4. 会议结束后立即采集总结可用度、修改类型和是否分享。
5. 每日查看失败漏斗：模型安装失败、录音失败、近实时转录失败、最终转录失败、总结失败。
6. 第 10 天根据通过标准做继续、修复后继续或停止的决定。

### 12.3 Go / No-Go

**继续投入：**

- 全链路完成率达到 90%；
- 不存在不可恢复的录音丢失；
- 总结可用率达到 70%；
- 至少一半测试用户愿意继续记录下一场会议。

**暂停扩展：**

- 出现不可恢复的录音丢失；
- 最终转录长期不稳定；
- 总结可用率低于 50%；
- 无账号模式下的数据隔离或删除机制存在严重缺陷。

在核心问题解决前，不增加 iOS、登录、多端同步、团队协作或更多导出能力。

## 15. 主要风险与应对

| 风险 | 触发信号 | 两周内应对 |
|---|---|---|
| Android 录音不稳定 | 音频缺段、文件损坏、进程被终止 | 限定测试机型、增量落盘、优先前台稳定性、每日压力测试 |
| 手机摆位导致音质差 | 远端说话人漏字明显 | 开始页给出桌面中央摆放提示，记录设备和环境 |
| 实时与最终文本混淆 | 用户认为会后文字变化是数据丢失 | 明确“临时/最终”标签，处理页解释重新转录 |
| 说话人分离不稳定 | 频繁串人或单人被拆成多人 | 允许批量重命名，不做身份推断 |
| AI 生成错误结论 | 总结与原文不符或补事实 | 结构化输出、证据强制绑定、空值规则和用户确认 |
| AI 总结隐私顾虑 | 用户不愿上传最终文本 | 录音前说明、音频不上传、总结前确认、24 小时上限、整场删除 |
| 无账号导致不可恢复 | 卸载或换机后历史丢失 | 首次使用明确提示，本地导出，设置页提供清除和保留说明 |
| 安装凭证丢失 | 无法查询或删除尚未清理的总结任务 | 后端设置 24 小时最长保留期限并自动清理 |
| 两周范围失控 | 新增登录、模板、团队或导出需求 | 新需求进入候选池，当前迭代只处理核心闭环阻断问题 |

## 16. 决策记录

| 决策 | 结论 | 原因 |
|---|---|---|
| 核心能力 | 实时转录 + 会后最终转录 + AI 总结 | 三者共同构成已确认的核心体验 |
| 事实源 | 本地录音 | 保障弱网和服务故障下仍可恢复 |
| 平台 | Android only | 两周期限下避免双端音频工程风险 |
| 身份体系 | 不设账号，不登录 | 降低首次使用成本，聚焦核心价值验证 |
| 数据形态 | 本地音频与转录 + 云端临时总结 | 不上传音频，无账号情况下避免建设云端个人工作区 |
| 产品形态 | 个人工具 | 砍掉团队、项目和待办系统 |
| 会议范围 | 通用主题，仅线下面对面会议 | 保持主题广度，同时控制采集方式 |
| 总结模板 | 统一五段式 | 避免多种会议模板造成范围膨胀 |
| 说话人 | 自动编号 + 手动重命名 | 提高可读性，不引入声纹身份系统 |
| 验证标准 | 5–10 人、20 场、90% 全链路、70% 总结可用 | 用真实使用结果而不是演示完成度判断 |

## 17. Alpha 完成定义

一名用户安装 App 并下载 Qwen3-ASR 模型后，无需注册或登录即可开始记录真实线下会议。App 能够稳定保存本地录音并展示句级近实时文字；完全断网时仍可完成录音和最终转录；联网后可生成带片段时间戳和证据的五段式 AI 总结；说话人分离失败时允许降级；用户能够核验、编辑、分享或删除结果；20 场试用数据达到既定门槛。

任何 iOS、登录、多端同步、团队协作、项目管理、更多会议模板、外部集成或私有化需求，只有在 Alpha 通过 Go / No-Go 后才重新评估。
