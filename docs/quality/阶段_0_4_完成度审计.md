# 阶段 0～4 完成度审计

> 状态：工程硬门槛通过，可合并 `dev`
> 审计日期：2026-07-31
> 评估范围：`phase-0-4`
> 技术边界：用户已确认以官方 Whisper C++ 主链为准

## 1. 判定原则

阶段 0～4 的集成判定只使用工程硬门槛：

- 事实 PCM 是唯一事实源，写盘不依赖 VAD/ASR。
- 会议开始后模型锁定，预览和最终转录不得自动切换或混合模型。
- 确定性静音零误检、chunk 一致性、取消与资源释放必须通过。
- VAD/ASR 失败或预览积压只能降级预览，不能丢失录音。
- 最终转录必须从完整 PCM 重跑，时间戳、排序和快照原子切换必须通过。
- Android 模拟器证据、模型资源、APK 审计和 Whisper C++ 许可必须可追溯。

真实产品会议准确率、噪声幻觉下降、语音首尾关键事实召回和 Preview 延迟已从
Hard Gate 取消。相关语料、人工复核、完整矩阵和派生指标仍保留为观察能力：

- 缺少证据时输出 `status=not_tested, blocking=false`。
- 有证据时如实输出 `passed` 或 `failed`，但不改变工程集成或 Alpha 发布决策。
- `not_tested` 不能折算成通过，也不得宣传产品会议质量已经验证。
- 公开或合成语料不得冒充 `product-meeting` 结果。

旧 `paraformerRedistributionConfirmed` 字段不得关闭 `license.whisperCpp`；Whisper C++
许可仍必须由当前字段和 NOTICE 证据独立确认。

## 5. 合并与发布边界

阶段 0～4 报告 `decision=go` 且 OCR 无未解决 Critical/High 后，可以合并 `dev`。
这只表示工程集成门槛通过，不表示 Alpha 已可发布。Alpha 发布仍需完成阶段 5～7 的
Android 真机性能与录音验证、Release APK 16 KB 审计、iOS arm64 无签名构建与产物
审计，以及全量自动化验证。iOS 真机项保持 `not_tested`，不执行真机测试。
