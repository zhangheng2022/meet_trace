# Step 17 结果页与数据控制

> 状态：已完成
> 日期：2026-07-25
> 需求映射：FR-040～FR-042、AT-10、AT-11

## 交付范围

- 会议结果页展示并播放本地完整录音。
- AI 证据定位当前最终片段并播放准确音频区间。
- 编辑转录文本和说话人时创建新的可审计最终快照。
- 转录版本变化后旧总结标记过期。
- 分享纯文本或 Markdown，默认不附带原始音频和本地路径。
- 二次确认删除会议，并清理其录音和全部数据库派生记录。
- 模型安装状态与历史会议记录解耦；当前唯一 SenseVoice 不提供删除入口。
- 设置页显示本地存储、卸载风险和诊断字段范围。
- 用户主动导出的诊断只含元数据、指标和错误码。

## 关键设计证据

### 可审计修订

`ReviseFinalTranscriptUseCase` 只接受当前活动、已完成的最终快照，并要求提交完整片段集合。任一片段缺失、文本为空、ID 重复或没有实际变化都会拒绝。成功时生成新快照和新片段 ID，保留原时间轴、置信度、模型 ID/版本，并经 SQLite CAS 原子切换活动快照。既有摘要由 Repository 标记为 `stale`。

### 证据与本地音频

结果页把证据的片段 ID、开始/结束时间和引文重新与当前最终快照核对。通过后，`PcmEvidencePlaybackService` 从 16 kHz 单声道 PCM16 事实文件读取对应字节区间，按 64 KiB 分块写入临时 WAV，再交给官方 `audioplayers` 播放。缺失文件、非法区间、越界或读取不完整均不会进入播放器。

### 分享和诊断隐私

`BuildMeetingShareUseCase` 只读取当前最终快照和总结，输出纯文本/Markdown，标注 AI 总结、待核对项和“不包含原始音频”。生产使用官方 `share_plus` 分享文本，不传音频附件。

诊断 JSON 使用固定字段白名单：

- schema 版本和生成时间；
- 应用、会议、模型和数据库字节数及设备可用空间；
- 会议状态计数和错误码计数；
- 模型 ID、版本、安装状态、字节数和错误码；
- 明示内容、音频、标题和路径均未包含的隐私标记。

测试使用包含“绝密董事会”、私有 meeting ID 和事实音频绝对路径的夹具，确认这些值均不出现在导出结果。

### 删除一致性

会议文件先移动到 `meetingsRoot` 内的 `.deleting-*` 暂存目录，然后调用 SQLite 会议删除，由外键级联清理转录快照、片段、总结和处理任务。数据库失败时恢复原目录；成功后才提交删除暂存目录。路径操作均验证目标严格位于会议根目录内。

会议行保存实际模型 ID/版本且不引用模型安装表，因此修复 SenseVoice 安装不会修改历史结果。当前不允许删除唯一模型。

## 测试先行证据

新增 13 项测试，覆盖：

- 编辑文本/说话人创建新快照并保留旧版本；
- 空文本、片段遗漏和无变化拒绝；
- 纯文本/Markdown 分享不含音频、文件名或本地路径；
- 会议删除的暂存、提交和数据库失败回滚；
- 证据时间映射为准确 PCM 字节和 WAV 头；
- 组件点击证据时把准确的事实音频路径和时间区间交给播放器；
- 音频缺失/区间越界不调用播放器；
- 实际目录回滚、提交和其他会议隔离；
- 诊断白名单不泄露标题、会议 ID、音频文件名或绝对路径。
- SenseVoice 下载处于忙碌状态时可执行暂停并保留分片。
