# 会迹（MeetTrace）Android + iOS Alpha 产品需求文档（无登录版）

> 版本：V0.9
> 日期：2026-08-03
> 状态：活动；产品范围与验收标准的唯一事实源
> 技术方案：[端侧 SenseVoice 转录技术方案](../technical/端侧_SenseVoice_转录技术方案.md)

## 1. 产品目标与边界

会迹是一款 Android + iOS 自适应的本地会议记录 Alpha。用户无需登录即可录音、查看会中临时转录，并在会议结束后基于完整事实音频生成带时间戳和说话人标签的最终转录。

产品边界：

- 本地音频是唯一事实源；ASR 变慢、积压、损坏或失败时录音必须继续。
- 不提供登录、跨设备同步、云端实时 ASR 或 AI 总结；App 不配置任何总结网关。
- 音频、转录和说话人结果默认只保存在设备上；只有用户主动执行独立的“分享音频”操作并二次确认后，临时 WAV 副本才进入系统分享面板。
- 当前 ASR 只支持 SenseVoice；其他模型待定，不承诺等级、发布时间或自动切换。
- Android 与 iOS 分别达到门槛后才允许发布，Android 证据不能替代 iOS 证据。

## 2. 当前模型决策

### 2.1 ASR

| 项目 | 固定值 |
| --- | --- |
| 模型 ID | `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17` |
| 模型版本 | `2024-07-17` |
| 推理接入 | 官方 `sherpa_onnx` Flutter/Dart 包 |
| 语言 | `auto` |
| ITN | `true` |
| 支持语言 | 普通话、粤语、英语、日语、韩语自动识别 |
| 分发 | 首次初始化按固定 Manifest 下载 |
| 安装包 | 不包含任何 ASR、VAD 或说话人权重 |

设置页保留全局默认模型选择器，当前仅显示真实可用的 SenseVoice。不得显示 Paraformer、Qwen、标准/高级等级、占位条目或“即将推出”。SenseVoice 是当前唯一模型，用户不能删除；可执行校验、下载、暂停、继续和修复。

### 2.2 说话人分离

| 项目 | 固定值 |
| --- | --- |
| 分段模型 | `sherpa-onnx-pyannote-segmentation-3-0/model.int8.onnx` |
| 嵌入模型 | `3dspeaker_speech_eres2net_base_sv_zh-cn_3dspeaker_16k.onnx` |
| 推理接入 | 官方 `sherpa_onnx` Dart `OfflineSpeakerDiarization` |
| 人数策略 | `numClusters=-1`，聚类阈值由固定普通话语料校准后锁定 |
| 质量承诺 | 普通话 2～4 人会议；其他语言可运行但不承诺分离准确率 |
| 分发 | 与 SenseVoice、Silero VAD 一同在首次初始化按固定 Manifest 下载 |
| 默认行为 | Debug 与 Release 全部会议默认开启，不设会议时长上限；设置中保留全局关闭开关 |

说话人分离是首次初始化阻断能力，但不是事实音频来源。录音期间不运行分离；会议结束后，最终 ASR 与离线说话人分离并行处理。两条任务结束后只发布一次最终快照；分离失败时写入明确的单一说话人降级结果，不得阻止最终文本落地或损坏事实音频。

当前官方 `sherpa_onnx 1.13.4` 及其上游 `master` 的 Dart `OfflineSpeakerDiarization.process*` 会为完整波形分配原生 `Float` 缓冲区但未释放；30 分钟 16 kHz 音频单次至少遗留 `115,200,000` B。2026-08-05 的产品决策接受该已知风险：Debug 与 Release 组合根均启用官方公开 API 的真实分离服务，所有会议默认开启，不设置会议时长上限，也不在开始会议前展示风险提示；设置中保留全局关闭开关，关闭后后续最终转录不启动分离。仍禁止通过私有包 API、自建 FFI 或原生桥接规避；运行失败、超时或资源不足时继续按单一说话人降级，事实录音和最终文本不得受损。

## 3. P0 范围

- 无登录本地工作区和自适应手机/平板 UI。
- 可靠事实录音、检查点、封存和崩溃恢复。
- SenseVoice、Silero VAD、Pyannote 分段模型与 3D-Speaker 嵌入模型的首次初始化下载、续传、校验和修复。
- 会中临时转录、有界积压和仅录音降级。
- 完整事实音频的最终转录、离线说话人分离、单次快照原子激活和重试。
- 自动说话人分离失败时的单一说话人降级，以及最终快照上的手工说话人标签修订。
- 创建会议时按本地开始时间生成稳定标题，例如 `2026-08-03 14:30 会议`；Alpha 不提供手动改标题。
- 文本分享与音频分享分开；音频经二次确认后临时封装为 WAV，分享完成后清理临时副本。
- Android/iOS 后台录音、系统中断、可访问性和安装包审计。

不在 Alpha 范围：登录、同步、云端实时 ASR、AI 总结、总结证据链、手动改会议标题、会中实时说话人分离、非普通话说话人准确率承诺、会议中切换模型、混合模型输出、自动替用户切换模型、下载远端“最新版本”、远程埋点、远程崩溃上报和应用内更新。

## 4. 首次初始化流程

1. App 完成本地数据库和服务初始化。
2. 读取固定 SenseVoice、Silero VAD 与说话人分离 Manifest。
3. 若本地安装记录、活动版本、固定文件集合和字节数均匹配，直接进入首页；该快速路径不得联网。
4. 未就绪时检查全部运行时模型资产总下载量不超过十进制 `300,000,000` 字节，并检查应用所在卷至少有 `1,073,741,824` 字节可用空间。
5. 无网络时停留在初始化页，显示离线原因和重试入口。
6. Wi-Fi/非计费网络自动开始下载。
7. 移动或未知网络先展示固定总量约 `286.3 MB`、可能产生数据费用和暂停后可续传；用户明确同意后下载。同意只对完全相同的 ASR、VAD 与说话人模型 ID、版本、哈希和大小集合生效，并持久化供续传使用。
8. 下载仅允许 HTTPS，使用 `.partial` 临时文件和 HTTP Range；暂停保留分片，校验失败不激活。
9. 全部资源均通过固定文件集、字节数和 SHA-256 校验后分别原子切换到活动目录；只有完整资源集合同时就绪才进入首页。
10. 用户拒绝、暂停或下载失败时留在初始化页；不得以仅录音模式绕过首次阻断。

当精确可用空间不足时，界面显示差额字节数。第二次启动的快速检查发现缺失/大小异常，或 Engine 初始化失败时，进入同一修复流程并执行完整校验。

## 5. 会议模型锁定

- 首页开始会议时直接读取全局默认 SenseVoice，不提供本场覆盖。
- 单模型基线：创建会议时原子保存录音模型、版本、`language=auto` 和 `ITN=true`；不再保存请求模型与回退原因。
- 录音开始后配置不可修改；会中预览和最终转录使用同一配置。
- 推理失败时转为仅录音，保留诊断和可重试入口，不自动切换或混合旧结果。
- 最终转录只基于完整事实音频；新快照成功激活前保留旧活动快照。
- 会议同时锁定说话人分段模型、嵌入模型和已校准的聚类配置；重试不得静默改用其他资源或阈值。

## 6. 功能要求

### FR-001 可靠录音

- PCM 音频写入与 ASR/VAD 独立运行。
- 有界队列可以丢弃最旧的预览任务，但不得丢失录音字节。
- 30 分钟会议音频完整率必须为 100%，并可播放到末尾。

### FR-002 初始化资源管理

- Manifest 固定资源 URL、大小、SHA-256、模型版本、最低 App 版本和许可 NOTICE。
- 全部运行时模型资产固定下载总量必须不超过 `300,000,000` 字节。
- 下载前最少可用空间为 `1,073,741,824` 字节。
- 支持断点续传、暂停、继续、失败重试、严格校验和原子激活。
- 不提供删除当前唯一模型的入口；模型与会议历史相互独立。

### FR-003 转录

- 单次识别窗口最大 15 秒，长语音用重叠窗口确定性合并。
- 每个片段包含全局 `start_ms/end_ms`、模型 ID、版本和修订状态。
- 预览失败不影响事实音频；最终转录失败不覆盖旧快照。

### FR-004 数据与隐私

- 音频、ASR、转录和说话人结果默认留在设备。
- 日志只记录白名单诊断字段，不记录音频或完整转录文本。
- 不接入远程埋点或远程崩溃上报；用户主动导出的诊断包不得包含音频或完整转录文本。
- 删除会议时级联删除该会议音频、转录、说话人标签、处理记录和分享临时文件。
- Alpha 升级采用全清数据策略：启动时检测到数据代不一致（含无数据代标记的历史安装），在打开数据库与初始化运行资源之前，清空整个应用数据根目录（数据库、会议音频与快照、已下载模型、录音检查点与偏好），随后重走首次初始化。数据代标记发生文件系统读取异常时必须阻断启动且不得执行清理。该策略的前提是 Alpha 内部用户量小、可接受丢失历史会议与已下载模型；引入第二模型或出现正式用户前必须重新评估。
- 数据库层对旧 schema 保留兜底拒绝；架构守卫禁止遗留模型选择列重新进入代码。

### FR-005 说话人分离

- 录音封存后，最终 ASR 与离线说话人分离从同一完整事实音频并行启动。
- 两条任务结束后合并为一次最终快照原子发布；ASR 失败时不发布不完整文本，分离失败时写入单一说话人降级结果。
- 自动人数通过固定阈值聚类估计，不要求用户预填人数，也不在 UI 暴露技术阈值。
- 用户可修改最终快照中的说话人显示标签；修订不改变事实音频和转录时间轴。

### FR-006 结果与分享

- 会议创建时按本地开始时间生成确定性标题，时区变化不追溯改写既有标题。
- 文本分享只包含会议标题、会议时间和带说话人标签及时间戳的最终转录。
- 音频分享是独立操作；每次展示会议名称、时长、文件大小和敏感信息提醒，二次确认后才生成临时 WAV 并打开系统分享面板。
- WAV 由事实 PCM 只读封装，不改写源音频；分享完成、取消或失败后都清理临时副本，空间不足时显示精确差额并阻止生成。

## 7. 性能与质量门槛

| 指标 | 门槛 |
| --- | --- |
| 全部运行时模型下载量 | ≤ `300,000,000` 字节（十进制） |
| 初始化空间预检 | ≥ `1,073,741,824` 可用字节 |
| SenseVoice RTF | P95 `< 0.5` |
| 结果延迟 | 语音段结束后 P95 `≤ 3 s` |
| 关键事实召回率 | `≥ 85%` |
| 普通话分离标注语料 | 2、3、4 人会议合计 `≥ 60` 分钟 |
| 说话人分离 DER | 总体 `≤ 25%` |
| 说话人数误差 | 绝对误差 `≤ 1` |
| 说话人分离 RTF | 30 分钟音频 `≤ 15` 分钟，即 `≤ 0.5` |
| 30 分钟音频完整率 | `100%` |

30 分钟目标设备测试必须记录绝对电量变化、起止温度、最高温度、内存峰值和热降频现象，不以相对旧模型的百分比替代。指标须在 Android 与 iOS 目标设备、同一固定语料上分别留证。

## 8. 验收场景

| ID | 场景 | 预期 |
| --- | --- | --- |
| AT-01 | 干净安装，安装包审计 | APK/IPA 不含 `.onnx`、模型 token、ASR/VAD/说话人权重或旧模型 ID |
| AT-02 | 首次启动 Wi-Fi | 自动下载约 286.3 MB；全部资源校验并激活后才进入首页 |
| AT-03 | 首次启动移动网络 | 未明确同意前不下载；同意绑定固定资源版本集合 |
| AT-04 | 暂停与重启 | 保留 `.partial`，继续时通过 Range 复用已下载字节 |
| AT-05 | 无网络/空间不足 | 留在初始化页；显示可操作错误与精确空间差额 |
| AT-06 | 第二次离线启动 | 全部运行时资源仅做本地快速检查，成功后直接进入首页，不远端查版本 |
| AT-07 | 缺失、损坏或 Engine 失败 | 进入修复流程，完整校验后恢复；不静默切换模型 |
| AT-08 | 设置页 | 仅一项 SenseVoice；无删除、等级、占位或待定入口 |
| AT-09 | 开始会议 | 锁定 ID、版本、auto 和 ITN，预览/最终共用 |
| AT-10 | ASR 积压或失败 | 允许丢预览任务，录音完整且继续 |
| AT-11 | 联合最终处理 | ASR 与分离并行；成功时一次发布最终快照，分离失败时发布单一说话人降级结果；ASR 失败保留音频和旧快照 |
| AT-12 | 30 分钟会议 | 音频 100% 完整，达到 RTF/延迟/召回并记录能耗温控 |
| AT-13 | 普通话说话人分离 | 2/3/4 人固定语料满足 DER、人数误差与 RTF 门槛，失败降级不损坏音频或文本 |
| AT-14 | 旧 Alpha 安装升级 | 提升数据代并全清旧数据后重走初始化；无残留旧数据库、音频、模型或检查点 |
| AT-15 | Android/iOS 系统中断 | 准确呈现平台状态，可恢复已落盘事实音频 |
| AT-16 | 手机/平板与无障碍 | 关键页面无溢出，返回手势、Dynamic Type/VoiceOver 可用 |
| AT-17 | 文本分享 | 只分享标题、时间和带说话人/时间戳的最终转录，不附带音频 |
| AT-18 | 音频分享 | 每次二次确认；临时 WAV 可播放且与源 PCM 时长一致，完成/取消/失败后无残留副本 |

## 9. Alpha 完成定义

- 自动化覆盖全部 Manifest、归档解包、下载上限、1 GiB 空间预检、移动网络同意、续传、校验、快速启动、锁定配置、联合快照、分离降级、WAV 分享清理和数据代门全清。
- `flutter analyze`、`flutter test`、Android Debug 构建和 APK 权重审计通过；Android 内部 Alpha 以 `com.meettrace.app` 的签名 APK 直发。
- Android 与 iOS 目标真机完成 AT-01～AT-18 的适用项；缺少任一平台证据时发布状态保持 `blocked`。iOS 内部 Alpha 通过 TestFlight 分发。
- 未解决的 OCR Critical/High 缺陷为零。
- 官方 `sherpa_onnx` Dart 完整波形缓冲区缺陷作为已接受的内部 Alpha 风险持续跟踪，不再单独阻断自动分离或内部构建；仍需记录 30 分钟重复任务内存、DER、人数误差与 RTF 证据，未满足 AT-13 时不得扩大分发范围或宣称质量达标。
- Web、Windows、Linux 与 macOS 工程壳不属于 Alpha 支持面，不进入发布结论。

## 10. 变更规则

新增或替换 ASR/说话人模型、恢复 AI 总结、改变首次阻断、下载上限、空间门槛、网络同意、联合最终快照、音频分享、会议锁定或发布门槛，均属于产品范围变化：必须先更新本 PRD 并运行 `$grill-me`，再修改代码和技术方案。
