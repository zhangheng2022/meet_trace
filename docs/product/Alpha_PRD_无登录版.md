## 1. 产品目标与边界

会迹是一款 Android、iOS 与 Windows 自适应的本地会议记录 Alpha。用户无需登录即可录音、查看会中临时转录，并在会议结束后基于完整事实音频生成带时间戳和说话人标签的最终转录。

- 本地音频是唯一事实源；ASR 变慢、积压、损坏或失败时录音必须继续。
- 不提供登录、跨设备同步、云端实时 ASR 或 AI 总结；App 不配置任何总结网关。
- 音频、转录和说话人结果默认只保存在设备上；只有用户主动执行独立的“分享音频”操作并二次确认后，临时 WAV 副本才进入系统分享面板。Android、iOS 与 Windows Release 默认启用可在设置中关闭的 Sentry 远程诊断；任何平台均不得把事实 PCM、WAV、转录快照或说话人结果作为 Attachment 或自定义 Payload 主动上传。
- 当前 ASR 只支持 SenseVoice；其他模型待定，不承诺等级、发布时间或自动切换。
- Android、iOS 与 Windows 必须基于同一候选提交完成构建、商店审核、自动化门禁和各平台定义的分发检查后，才允许对外发布该 Alpha；不要求提交目标设备人工验收证据。任一平台的构建、审核、自动化或分发门禁失败均阻断统一发布。
- Android 候选 APK 只构建 `arm64-v8a`，Windows 候选只构建 x64 MSIX。公开前 Android APK 暂存在 GitHub Draft Release；Windows Store MSIX 只进入候选 Actions Artifact，由自动化核对 SHA-256、包身份、版本与架构后，把该确切文件先提交固定 Package Flight。Flight 取得 `Published` 精确包回执后，才把同一 MSIX 提交为 100% 正式 non-flighted submission；正式 submission 取得 `Published/Public` 精确包回执后，才发布同一 Draft 为 GitHub Pre-release。Windows 发布门禁不证明 Store 客户端安装、启动、更新或卸载行为，不依赖专用机或自托管 runner；MSIX 不进入 GitHub Release，不得重建、覆盖资产或移动已有标签。
- iOS Alpha 的编译与分发最低版本为 iOS 15；从当前候选起不再支持 iOS 13/14，也不为已安装旧 TestFlight 构建提供专门迁移版。iOS 候选只通过 TestFlight 分发，不在 GitHub Release 上传 IPA。候选必须被自动加入固定外部测试组、提交 Beta App Review，并在审核通过后进入 `Testing`、启用自动通知和稳定 public link；不得伪造链接或绕过 Beta App Review。
- Windows 最低支持 Windows 10 22H2 与 Windows 11，仅支持 x64；8 GB RAM、普通四核 CPU、无独立显卡作为非阻断性能观测基线。低于 8 GB 允许安装和事实录音，但必须明确提示推理性能可能受限。
- Windows 首版只采集麦克风，不采集或混合系统播放音频；不得以“支持 Windows”暗示可以直接捕获同机线上会议的系统声音。
- Alpha 仅支持当前公开版本，不承诺任意 Alpha 版本之间的安装升级、本地数据格式、数据库、历史会议、事实录音、转录、模型缓存、录音检查点或设置兼容性，也不支持降级或数据迁移。更新和统一发布链路是已批准候选的安全分发能力，不构成兼容性承诺。

## 2. 当前模型决策

### 2.1 ASR

| 项目 | 固定值 |
| --- | --- |
| 模型 ID | `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17` |
| 模型版本 | `2024-07-17` |
| 推理接入 | 官方 `sherpa_onnx` Flutter/Dart 包 |
| 语言 | `auto` |
| ITN | `true` |
| 支持语言 | 普通话、粤语、英语、日语、韩语自动识别 |
| 分发 | 首次初始化按固定 Manifest 下载 |
| 安装包 | 不包含任何 ASR、VAD 或说话人权重 |

设置页保留全局默认模型选择器，当前仅显示真实可用的 SenseVoice。不得显示 Paraformer、Qwen、标准/高级等级、占位条目或“即将推出”。SenseVoice 是当前唯一模型，用户不能删除；可执行校验、下载、暂停、继续和修复。

### 2.2 说话人分离

| 项目 | 固定值 |
| --- | --- |
| 分段模型 | `sherpa-onnx-pyannote-segmentation-3-0/model.int8.onnx` |
| 嵌入模型 | `3dspeaker_speech_eres2net_base_sv_zh-cn_3dspeaker_16k.onnx` |
| 推理接入 | 官方 `sherpa_onnx` Dart `OfflineSpeakerDiarization` |
| 人数策略 | `numClusters=-1`，聚类阈值由固定普通话语料校准后锁定 |
| 质量承诺 | 普通话 2～4 人会议；其他语言可运行但不承诺分离准确率 |
| 分发 | 与 SenseVoice、Silero VAD 一同在首次初始化按固定 Manifest 下载 |
| 默认行为 | Debug 与 Release 全部会议默认开启，不设会议时长上限；设置中保留全局关闭开关 |

说话人分离是首次初始化阻断能力，但不是事实音频来源。录音期间不运行分离；会议结束后，最终 ASR 与离线说话人分离并行处理。两条任务结束后只发布一次最终快照；分离失败时写入明确的单一说话人降级结果，不得阻止最终文本落地或损坏事实音频。

固定依赖为官方 `sherpa_onnx 1.13.6`。Debug 与 Release 均使用公开 API；禁止私有包 API、自建 FFI 或原生桥。重复长会议内存只作非阻断观测，运行失败、超时或资源不足时降级为单一说话人，事实录音和最终文本不得受损。

## 3. P0 范围

- 无登录本地工作区和自适应手机、平板与 Windows 桌面 UI。
- 可靠事实录音、检查点、封存和崩溃恢复。
- SenseVoice、Silero VAD、Pyannote 分段模型与 3D-Speaker 嵌入模型的首次初始化下载、续传、校验和修复。
- 会中临时转录、有界积压和仅录音降级。
- 完整事实音频的最终转录、离线说话人分离、单次快照原子激活、重试、失败降级和标签修订。
- 创建会议时按本地开始时间生成稳定标题，例如 `2026-08-03 14:30 会议`；用户可在会议列表重命名任意未删除会议。
- 文本分享与音频分享分开；音频经二次确认后临时封装为 WAV，分享完成后清理临时副本。
- Android/iOS 后台录音、Windows 托盘持续录音、三平台系统中断、可访问性和安装包审计。
- Windows 全局麦克风选择、会议输入设备锁定、设备断开恢复、单实例和安全退出。
- 全平台外观主题支持跟随系统、浅色和深色；默认跟随系统，用户选择仅保存在本机并即时作用于整个应用。
- 全平台应用界面支持简体中文与英文；默认跟随系统，任意 `zh-*` 使用简体中文，其余未支持语言回退英文。用户可在设置页手动选择并仅保存在本机，切换立即生效且不得重建或中断录音、ASR 与会议锁定配置。
- Android、iOS 与 Windows Release 默认开启可退出的 Sentry 错误监控、性能追踪与匿名录音性能窗口；远程诊断失败不得阻断或拖慢事实录音与最终处理。
- 单一 Alpha 频道的全平台自动更新；只能发现三平台构建、自动化和分发门禁均通过的公开候选，录音或最终处理期间不得强制安装、退出或清理。该能力不要求旧 Alpha 可升级或保留数据。

不在 Alpha 范围：登录、同步、云端实时 ASR、AI 总结、总结证据链、会中实时说话人分离、非普通话说话人准确率承诺、会议中切换模型、混合模型输出、自动替用户切换模型、业务分析埋点、Windows ARM64/32 位、Windows 7/8、系统音频录制、多个应用实例、多窗口、开机自启、复杂快捷键、拖拽导入和自定义更新频道。

## 4. 首次初始化流程

1. App 完成本地数据库和服务初始化。
2. 读取固定 SenseVoice、Silero VAD 与说话人分离 Manifest。
3. 若本地安装记录、活动版本、固定文件集合和字节数均匹配，直接进入首页；该快速路径不得联网。
4. 未就绪时检查全部运行时模型资产总下载量不超过十进制 `300,000,000` 字节，并检查应用所在卷至少有 `1,073,741,824` 字节可用空间。
5. 无网络时停留在初始化页，显示离线原因和重试入口。
6. Android/iOS 的 Wi-Fi/非计费网络自动开始下载；移动或未知网络先展示固定总量约 `286.3 MB`、可能产生数据费用和暂停后可续传，用户明确同意后下载。同意只对完全相同的 ASR、VAD 与说话人模型 ID、版本、哈希和大小集合生效，并持久化供续传使用。
7. Windows 在空间预检和固定 Manifest 校验通过后自动开始下载，不要求网络确认；界面必须显示总量与进度，并允许暂停、续传和重试。
8. 下载仅允许 HTTPS，使用 `.partial` 临时文件和 HTTP Range；暂停保留分片，校验失败不激活。
9. 全部资源均通过固定文件集、字节数和 SHA-256 校验后分别原子切换到活动目录；只有完整资源集合同时就绪才进入首页。
10. 用户拒绝、暂停或下载失败时留在初始化页；不得以仅录音模式绕过首次阻断。

当精确可用空间不足时，界面显示差额字节数。第二次启动的快速检查发现缺失/大小异常，或 Engine 初始化失败时，进入同一修复流程并执行完整校验。

## 5. 会议模型锁定

- 首页开始会议时直接读取全局默认 SenseVoice，不提供本场覆盖。
- 单模型基线：创建会议时原子保存录音模型、版本、`language=auto` 和 `ITN=true`；不再保存请求模型与回退原因。
- 录音开始后配置不可修改；会中预览和最终转录使用同一配置。
- 推理失败时转为仅录音，保留诊断和可重试入口，不自动切换或混合旧结果。
- 最终转录只基于完整事实音频；新快照成功激活前保留旧活动快照。
- “基于完整事实音频”指事实 PCM 是唯一输入和可重试来源；最终 ASR 先流式扫描整份 PCM，通过已校验的 Silero VAD 选择语音区间，不读取或拼接会中预览文本。
- 会议同时锁定说话人分段模型、嵌入模型和已校准的聚类配置；重试不得静默改用其他资源或阈值。

## 6. 功能要求

### FR-001 可靠录音

- PCM 音频写入与 ASR/VAD 独立运行。
- 有界队列可以丢弃最旧的预览任务，但不得丢失录音字节。
- 30 分钟会议音频完整率必须为 100%，并可播放到末尾。
- Windows 首版只采集 16 kHz 单声道 PCM16 麦克风输入。设置保存全局默认输入设备，开始会议时锁定实际设备，设备仍可用时不得静默切换。
- Windows 录音中设备断开时立即刷新检查点并仅尝试一次切换到当前系统默认麦克风；成功后在同一会议记录中断时间与设备变化，没有可用设备时进入真实的“录音已中断”状态并等待恢复。
- Windows 锁屏、最小化和失去焦点时继续录音；睡眠/休眠期间不承诺采集，恢复后继续同一会议并记录音频缺口。注销、关机或强制退出时尽力封存已写 PCM，下次启动使用检查点恢复。

### FR-002 初始化资源管理

- Manifest 固定资源 URL、大小、SHA-256、模型版本、最低 App 版本和许可 NOTICE。
- 全部运行时模型资产固定下载总量必须不超过 `300,000,000` 字节。
- 下载前最少可用空间为 `1,073,741,824` 字节。
- 支持断点续传、暂停、继续、失败重试、严格校验和原子激活。
- 不提供删除当前唯一模型的入口；模型与会议历史相互独立。

### FR-003 转录

- 单次识别窗口最大 15 秒，长语音用重叠窗口确定性合并。
- 最终 ASR 对每个 VAD 语音区间独立识别；语音本身不超过 15 秒时缩减上下文并保持单窗口，只有语音本身超过 15 秒时才使用 500 ms 重叠窗口。全静音会议直接生成空的已完成快照，不初始化 SenseVoice。
- 最终 VAD 创建、扫描或输出校验失败时，最终转录必须以可重试错误结束并保留事实音频与旧活动快照；不得把 VAD 故障判成静音，也不得回退固定时间硬切后发布低质量最终文本。VAD 已成功生成片段后的释放异常只记录诊断，不能推翻有效片段。
- 每个片段包含全局 `start_ms/end_ms`、模型 ID、版本和修订状态。
- 预览失败不影响事实音频；最终转录失败不覆盖旧快照。

### FR-004 数据与隐私

- 音频、ASR、转录和说话人结果默认留在设备。
- Android、iOS 与 Windows 的可分发 Release 默认启用 Sentry；Debug/Profile 默认关闭，只允许受控诊断构建显式启用 `development` 环境。三平台共用一个 Sentry 项目，候选显式使用 `com.meettrace.app@<version>+<共享构建号>` 作为 `release`、共享构建号作为 `dist`。生产 DSN、`release/dist` 或必需符号上传凭据缺失时必须阻断候选，不能静默降级为关闭；SDK 初始化、采集、缓存或上传失败仍不得阻断 App 启动、事实录音或最终处理。
- 首次安装按默认开启语义在应用最早启动阶段初始化 Sentry，并在首屏展示一次可关闭、非阻断的远程诊断告知；设置页提供仅保存在本机的开关并默认开启。后续启动先读取开关，关闭时不初始化；开关读取异常时本次进程按关闭处理，不得覆盖已有退出选择，也不得阻断本地启动。运行中关闭须立即停止应用侧新错误、Tracing、Metrics 和当前 60 秒窗口，不回填；已交给 SDK、已进入原生缓存或已上传的数据不能保证撤回，Windows 原生崩溃处理最迟在下次启动时完全关闭。重新开启后立即恢复错误监控，并从下一个 60 秒边界重新抽样性能会话。
- 未处理错误、Flutter `silent` 框架错误和后台 Isolate 未处理异常均按 100% 采集，并附带必要堆栈；预期的网络超时、资源未齐、用户取消和可恢复业务状态只记脱敏 Span/Breadcrumb，不手动创建 Issue。启用匿名 Release Health；只允许 SDK 使用随进程重启失效的随机 Session ID 和各次 Trace ID，不设置用户、设备、安装或会议持久标识。SDK 可在下次启动结算上次异常退出的会话，但旧 ID 不得复用于新进程。
- 性能会话在每次进程启动或运行中重新开启后随机抽样一次，生产抽样率为 20%；应用保存本进程抽样结果，并由公开 `tracesSampler` 对本进程返回 `1.0` 或 `0.0`，不得用逐 Transaction 的 `0.2` 代替。被抽样会话持续采集应用启动、命名路由导航、模型下载与初始化、录音开始、安全封存、最终 ASR 和说话人分离阶段的名称、耗时、成功/失败及粗粒度错误类型。会议列表、录音、会议详情和设置均采集 TTID；仅会议列表就绪、录音就绪和会议详情加载完成采集 TTFD。关闭用户交互 Tracing 和用户交互 Breadcrumb。
- 被抽样的录音会话每 60 秒生成匿名性能窗口，包含 PCM 写入延迟、写入积压、预览队列积压与丢弃数、录音中断/恢复次数和窗口时长；不得包含音频大小、会议时长、路径、内容或会议标识。窗口立即交给 SDK，录音链路不得等待上传结果。Android/iOS 使用 SDK 原生离线缓存并将 `maxCacheItems` 设为 10；Windows 的 Dart 错误、Span 和 Metrics 在线发送，失败即丢，Crashpad 只持久化平台原生崩溃。不得为统一缓存语义自建传输层。系统允许时不因网络类型、后台或低电量主动暂停诊断上传。
- 平台共同验收 Dart/Flutter 错误、手动 Tracing/Metrics、统一 `release/dist`、符号化和 Dart 启动 Span。Android 另采集原生崩溃、ANR、Android 12+ Tombstone 与卡帧；iOS 另采集原生崩溃、App Hang、Watchdog 与卡帧；Windows x64 使用 SDK 的 Crashpad 原生崩溃与 minidump 符号化。为保证后续启动可在 SDK 初始化前读取退出开关，三平台均不承诺需要在 Flutter Binding 前初始化的自动原生 App Start，不虚构移动端或桌面端启动能力。
- 应用全部 Dart HTTP 客户端统一使用官方 `SentryHttpClient` 自动采集请求与失败，但只允许保留域名、HTTP 方法、状态码和耗时；必须删除完整路径、查询参数、请求头、请求体、响应体和下载文件名。关闭原生全局失败请求采集、请求体采集和 `sentry-trace`、`baggage`、`traceparent` 传播；所有网络 Span 和错误在发送前通过公开 Hook 执行同一脱敏规则。
- 每个错误最多附带 100 条脱敏 Breadcrumb，可覆盖应用前后台、网络连接、内存压力、静态命名路由、录音/封存/最终 ASR/分离阶段、资源校验、模型初始化、下载/更新阶段和脱敏 HTTP 状态；禁止控件文字、具体点击、音频/转录内容、会议或文件标识、完整 URL、原始日志及用户操作内容。Breadcrumb 只随错误事件上传，不作为独立持续遥测。
- `sendDefaultPii=false`；禁止 Session Replay、结构化日志、业务分析指标、截图、View Hierarchy、用户交互追踪、用户反馈、附件、完整依赖清单和任何用户标识。Production 禁止 Profiling；仅 iOS 受控诊断构建可显式启用 Profiling，且不得使用生产 `release/dist`。允许 Sentry Client Reports 仅上报被丢弃事件的类型、原因与数量。
- 设备与运行环境只允许 App 版本/构建号、平台、OS 版本、设备型号、CPU 架构、内存压力等级、前后台状态和 locale code。禁止设备名称、广告 ID、安装 ID、运营商、精确时区、IP 推断位置和持久用户 ID。错误堆栈可包含应用源码包内路径、函数名与行号；录音、模型、临时文件及其他用户数据运行时路径仍禁止上传。
- Sentry 项目必须关闭 IP 存储与地理推断、启用敏感字段清洗，并将服务端保留期设为账户支持的最短值且不超过 30 天。删除会议、卸载或关闭诊断只影响本地及后续采集，不能追溯删除匿名远程历史；隐私政策和设置文案必须明确披露。
- 三平台候选必须在公开前上传 Dart `split-debug-info`、混淆映射及平台必需的原生调试符号并验证可符号化；禁止上传完整源码和 Web source maps，任一平台符号化失败均阻断统一发布。受控验证事件不得使用生产 Release，验证后删除人工测试 Issue。新出现或回归的 Fatal、原生崩溃、ANR、App Hang/Watchdog 按 Issue 聚合通知项目维护者；性能只进入 Dashboard，不触发告警或发布阈值。
- Sentry 不得主动附加事实 PCM、WAV、转录快照或说话人结果。用户主动导出的诊断包仍不得包含音频或完整转录文本。
- 删除会议时级联删除该会议音频、转录、说话人标签、处理记录和分享临时文件。
- Alpha 不提供数据迁移。启动时检测到数据代不一致（含无数据代标记的历史安装），在打开数据库与初始化运行资源之前，清空整个应用数据根目录（数据库、历史会议音频与快照、已下载模型、录音检查点与偏好），随后重走首次初始化。数据代标记发生文件系统读取异常时必须阻断启动且不得执行清理。通过应用内更新入口安装提高数据代的破坏性 Alpha 前，必须明确说明清除范围并由用户确认；录音或最终处理期间不得触发安装或清理。该策略的前提是 Alpha 内部用户量小、可接受丢失全部本地数据；引入第二模型或出现正式用户前必须重新评估。
- 数据库层对旧 schema 保留兜底拒绝；架构守卫禁止遗留模型选择列重新进入代码。

### FR-005 说话人分离

- 录音封存后，最终 ASR 与离线说话人分离从同一完整事实音频并行启动。
- 两条任务结束后合并为一次最终快照原子发布；ASR 失败时不发布不完整文本，分离失败时写入单一说话人降级结果。
- 自动人数通过固定阈值聚类估计，不要求用户预填人数，也不在 UI 暴露技术阈值。
- 用户可修改最终快照中的说话人显示标签；修订不改变事实音频和转录时间轴。

### FR-006 结果与分享

- 会议创建时按本地开始时间生成确定性标题，时区变化不追溯改写既有标题。
- 用户可在会议列表重命名任意未删除会议，包括录音中、处理中、已完成和失败状态。标题自动去除首尾空格，只允许单行 1～60 个字符，允许重名；保存失败时保留输入内容并允许重试。
- 重命名只更新会议标题元数据，不改写事实 PCM、会议时间、转录、快照或已经分享的内容；后台状态写入不得覆盖新标题。新标题用于后续列表、详情、文本分享和音频分享名称。
- 文本分享只包含会议标题、会议时间和带说话人标签及时间戳的最终转录。
- 音频分享是独立操作；每次展示会议名称、时长、文件大小和敏感信息提醒，二次确认后才生成临时 WAV 并打开系统分享面板。
- WAV 由事实 PCM 只读封装，不改写源音频；分享完成、取消或失败后都清理临时副本，空间不足时显示精确差额并阻止生成。

### FR-007 Windows 桌面运行

- Windows 只允许一个 MeetTrace 进程实例；再次启动时激活已有窗口，托盘录音中不得创建第二个会话。
- 未录音时关闭窗口正常退出；录音中关闭窗口改为最小化到系统托盘并显示录音仍在继续。用户只能在应用内明确停止会议，或从托盘执行“停止并退出”。
- 使用现有内容驱动断点和 Forui 主题。宽屏保留会议列表/预览主从布局以及详情事实栏/工作区布局；不得为 Windows 复制业务页面或创建独立 ViewModel。
- Windows 窗口可缩放，最小内容尺寸约 `840×640`；补齐鼠标、键盘焦点、Tab 顺序、Enter/Space 操作和 Windows 屏幕阅读器语义。首版不做完整 Windows 原生风格重设计。
- 数据库、模型、事实 PCM、转录和检查点固定使用 MSIX 应用本地私有数据目录，不写安装目录、不进入漫游数据，也不提供自选磁盘或迁移数据目录。

### FR-008 全平台自动更新

- 自动更新和统一发布只负责发现、验证和分发当前公开 Alpha，不承诺已安装旧 Alpha 能够系统升级、继续读取旧数据或迁移到新版本；仅当前公开 Alpha 受支持。
- 应用只消费已通过三平台验收的公开、签名、不可变更新 Manifest；检查失败不得阻断启动、录音、最终处理或本地历史访问。
- Android 自动检查并下载 `arm64-v8a` APK，严格校验版本、长度、SHA-256、包名和签名证书，再交由系统安装器；始终兼容系统要求的用户确认或未知来源授权，不宣称静默安装。
- Android 候选清单和签名更新 Manifest 必须携带 APK 实测 `versionCode`；客户端按该值验包，不根据共享构建号或 ABI 自行计算。新序列按 `2001 → 2002 → 2003` 递增。
- iOS 继续由 TestFlight 分发和更新；应用不得自行替换安装包，实际自动安装受用户 TestFlight/App Store 设置和 Apple 平台规则控制。
- Windows 只通过 Microsoft Store 产品 `9PHHSJMWK06G` 检查、安装和更新；更新 Manifest 必须拒绝 `.appinstaller` 或其他 Store 产品/包身份。应用运行、录音或最终处理期间不得强制退出或安装。
- 更新不阻断应用启动、不允许降级。若新版本提高数据代并将全清本地数据，必须在安装前展示醒目风险；不得通过静默更新绕过该提示。

### FR-009 外观主题

- Android、iOS 与 Windows 使用同一组 Forui 浅色和深色语义令牌，不复制平台页面或业务状态。
- 设置页提供“跟随系统”“浅色”“深色”三个互斥选项，默认“跟随系统”；选择保存到本地 `app_settings`，重启后恢复并立即作用于整个应用。
- “跟随系统”必须响应运行中的系统亮度变化；固定浅色或深色时不受系统亮度变化影响。
- 主题偏好缺失、未知或读取失败时回退“跟随系统”，不得阻断首次初始化、历史访问、录音或最终处理。

### FR-010 应用语言

- 应用自有界面、错误提示、初始化、无障碍文案、分享外壳和新会议默认名称支持简体中文与英文；`SenseVoice`、转录内容和品牌名“会迹 MeetTrace”不翻译。
- 默认跟随系统：任意 `zh-*` 使用简体中文，其他未支持语言回退英文。设置页提供“跟随系统”“简体中文”“English”三个互斥选项；用户选择保存到本地 `app_settings` 并立即作用于整个应用。
- 语言切换只刷新展示文案，不重建、不切换且不中断事实录音、ASR、最终处理或本场锁定配置；偏好缺失、未知或读取失败时回退跟随系统。
- 新会议默认名称按创建时应用语言生成并永久保存；已有会议名称不追溯改写。分享外壳和日期时间格式使用分享或查看时的当前应用语言，存储时间、排序、转录文本和已分享内容不变。

## 7. 性能与质量观测目标

下列运行指标用于工程优化与风险观察，不要求按候选或平台提交目标设备证据，也不阻断 Alpha 构建、分发或统一发布。资源下载量和初始化空间仍属于功能硬约束。

| 指标 | 目标 |
| --- | --- |
| 全部运行时模型下载量 | ≤ `300,000,000` 字节（十进制） |
| 初始化空间预检 | ≥ `1,073,741,824` 可用字节 |
| SenseVoice RTF | P95 `< 0.5` |
| 结果延迟 | 语音段结束后 P95 `≤ 3 s` |
| 关键事实召回率 | `≥ 85%` |
| 普通话分离标注语料 | 2、3、4 人会议合计 `≥ 60` 分钟 |
| 说话人分离 DER | 总体 `≤ 25%` |
| 说话人数误差 | 绝对误差 `≤ 1` |
| 说话人分离 RTF | 30 分钟音频 `≤ 15` 分钟，即 `≤ 0.5` |
| 30 分钟音频完整率 | `100%` |

团队可按需要运行固定语料或长会议基准，记录 RTF、延迟、召回率、DER、人数误差、内存、能耗和温控；这些结果只用于工程判断，不进入候选发布结论。
