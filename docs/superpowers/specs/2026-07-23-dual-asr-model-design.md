# Meetily 双 ASR 模型设计

> 状态：对话设计已确认，待书面审核
> 日期：2026-07-23
> 影响范围：Android Alpha、端侧模型管理、实时转录、最终转录、设置与开始会议流程

## 1. 目标

Meetily 增加一个面向低功耗和低端设备的标准模型，并将现有 Qwen3-ASR 0.6B INT8 定义为高级模型。

标准模型必须随 APK 安装、无需联网即可开始第一场会议；高级模型由用户按需下载。用户选择的模型同时负责该场会议的会中临时转录和会后最终转录。

本次变更不得破坏以下产品原则：

- 本地音频仍是唯一事实源。
- 推理变慢或失败时，录音必须继续。
- AI 总结只读取最终转录。
- 音频、临时转录、最终转录和模型推理默认留在本机。
- 关键总结内容继续绑定带时间戳的本地转录证据。

## 2. 范围

### 2.1 进入范围

- 两级端侧 ASR 模型：标准模型与高级模型。
- 标准模型随 APK 内置。
- 高级模型按需下载、校验、更新和删除。
- 设置页保存全局默认模型。
- 开始会议页允许覆盖本场模型。
- 会议创建后锁定模型。
- 模型失败、降级和完整音频重新转录。
- 两个模型的统一性能、准确率和可靠性评测。

### 2.2 不进入范围

- 会议进行中自动或手动切换模型。
- 同一份临时转录混合两个模型的结果。
- 根据设备自动替用户决定模型。
- Qwen3-ASR 1.7B。
- 云端 ASR。
- 新增登录、同步、团队或多设备模型策略。
- 为标准模型承诺方言、多语言或词级时间戳。

## 3. 模型决策

| 层级 | 模型 | 安装方式 | 语言承诺 | 产品定位 |
|---|---|---|---|---|
| 标准 | `sherpa-onnx-paraformer-zh-small-2024-03-09` INT8 | 随 APK 内置 | 普通话、英语 | 低功耗、低端设备、开箱即用 |
| 高级 | `sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25` | 用户按需下载 | 以 Qwen3-ASR 官方能力和真机评测为准 | 准确率优先、更多语言和方言、资源占用更高 |

标准模型的 INT8 ONNX 文件约 79 MB。高级模型完整资源约 941 MB。最终发布使用的每个文件名、字节数、SHA-256、下载 URL 和许可信息必须进入版本化模型 Manifest，不能散落在业务代码中。

标准模型虽然内置于 APK，首次运行仍可将模型资源复制到 App 私有模型目录并校验。该过程不需要网络，界面显示“正在准备标准模型”，失败时允许进入仅录音模式。

## 4. 核心架构

### 4.1 统一模型描述

领域层增加不可变 `AsrModelDescriptor`，至少包含：

```text
modelId
displayName
tier
version
supportedLanguages
installationType
requiredBytes
capabilities
```

其中：

- `tier` 取值为 `standard` 或 `advanced`。
- `installationType` 取值为 `bundled` 或 `downloadable`。
- `capabilities` 只描述已经验证的能力，不根据模型宣传材料推断。

### 4.2 统一引擎接口

Paraformer 与 Qwen3-ASR 分别实现同一个 `AsrEngine` 接口。UI、ViewModel、Use Case 和 Repository 不得导入具体模型类型。

```dart
abstract interface class AsrEngine {
  AsrModelDescriptor get descriptor;

  Future<void> initialize();

  Stream<TranscriptEvent> get events;

  Future<void> acceptAudio(
    Float32List samples, {
    required int sampleRate,
    required int startMs,
  });

  Future<TranscriptSnapshot> finalizeMeeting(AudioSource source);

  Future<void> dispose();
}
```

`AsrEngineFactory` 根据已确认的 `modelId` 创建具体引擎。Factory 只负责选择和组装，不持有 UI 状态。

### 4.3 会议模型锁定

创建会议时保存：

```text
requestedModelId
recordingModelId
modelVersion
```

- `requestedModelId` 是用户最初选择。
- `recordingModelId` 是开始录音前最终确认的实际模型。
- 若高级模型不可用并由用户确认改用标准模型，两者可以不同。
- 开始录音后 `recordingModelId` 不可修改。
- 临时片段记录实际 `modelId` 和 `modelVersion`。
- 每个最终快照独立记录实际使用的模型。

## 5. 模型生命周期

### 5.1 标准模型

1. 模型资源打入 APK。
2. App 首次启动或首次转录前，将资源准备到私有模型目录。
3. 校验文件大小和 SHA-256。
4. 使用临时目录和原子重命名完成安装。
5. 标准模型不能由用户删除。
6. 标准模型不可用时，已有会议仍可访问，新会议允许仅录音。

### 5.2 高级模型

1. 用户在设置页或开始会议页触发下载。
2. 下载前检查网络类型和至少 2 GB 可用空间。
3. 支持进度、取消、安全重试和校验。
4. 新版本安装失败时保留上一可用版本。
5. 用户可以删除高级模型文件；删除不影响历史会议、转录和总结。
6. 高级模型未安装、校验失败或初始化失败时，用户可以明确改用标准模型。

### 5.3 模型更新

- 标准模型随 App 版本更新。
- 高级模型由远端 Manifest 提供新版本。
- 更新使用临时目录、逐文件校验和原子切换。
- 正在录音或处理会议时不得替换正在使用的模型版本。
- 旧版本只有在不存在活动任务后才能清理。

## 6. 用户交互

### 6.1 设置页

新增“转录模型”区域：

- 标准模型显示“默认、低功耗、普通话与英语、已安装”。
- 高级模型显示“准确率优先、资源占用较高”。
- 高级模型展示下载大小、可用空间、Wi-Fi 建议、版本和安装状态。
- 提供高级模型下载、暂停或取消、重试、更新和删除入口。
- 设置页保存全局默认模型，初始值为标准模型。

### 6.2 开始会议页

- 默认继承设置中的模型。
- 模型选择折叠展示，不增加开始会议的必经步骤。
- 用户可以覆盖本场模型。
- 选择未安装的高级模型时，必须先完成下载，或取消后改用标准模型。
- 开始前显示高级模型的耗电、内存和发热提示。
- 模型确认后创建会议并锁定选择。

### 6.3 历史会议

- 切换全局默认模型不修改历史会议。
- 结果页可以显示该快照使用的模型。
- 用户重新转录历史会议时，可以选择当前已安装模型。
- 新快照成功写入前保留旧快照。
- AI 总结只读取当前激活的最终快照。

## 7. 数据流

```text
全局默认模型
  → 开始会议页本场覆盖
  → 检查安装与设备状态
  → 用户确认实际模型
  → 创建 Meeting 并锁定 recordingModelId
  → AsrEngineFactory 创建引擎
  → Silero VAD 生成统一音频时间区间
  → 会中临时转录
  → 封存完整本地音频
  → 同模型会后最终转录
  → 保存带 actualModelId 的最终快照
  → AI 总结与证据校验
```

两种模型共用：

- 16 kHz、单声道、PCM16 录音事实源。
- Silero VAD 分段和全局 `start_ms/end_ms`。
- 有界实时预览队列。
- `TranscriptEvent`、`TranscriptSegment` 和 `TranscriptSnapshot`。
- 证据映射、播放定位、编辑、分享和删除流程。

## 8. 失败与降级

| 场景 | 系统行为 |
|---|---|
| 标准模型资源缺失或损坏 | 允许仅录音，提示重新安装 App；不得判定录音失败 |
| 高级模型下载失败 | 保留已下载的安全状态和旧版本，允许改用标准模型 |
| 高级模型校验失败 | 删除未安装的临时文件，不覆盖旧版本 |
| 开始会议前高级模型初始化失败 | 显示原因，由用户确认改用标准模型 |
| 录音中模型推理失败 | 录音继续，实时转录进入降级状态，不中途混用另一模型 |
| 会后原模型重试失败 | 保留音频和旧快照，允许用户选择标准模型重新处理完整音频 |
| 模型队列积压 | 暂停或丢弃可重建的实时预览任务，不丢弃本地音频 |
| 高级模型设备性能未达标 | 显示性能风险；不标记为推荐或稳定支持 |

任何回退都必须显式记录并在界面可见。系统不得把两个模型生成的片段拼成同一个未标注来源的最终快照。

## 9. 性能与质量门槛

### 9.1 标准模型

| 指标 | 门槛 |
|---|---:|
| 模型资源体积 | ≤ 100 MB，不含公共运行库 |
| 最低目标设备 RTF P95 | `< 0.5` |
| 句后出字 P95 | `≤ 3 秒` |
| 30 分钟最终转录 | `≤ 5 分钟` |
| 录音完整率 | 100% |
| 温控 | 30 分钟内不持续进入 Severe/Critical |
| 相对能耗 | 同设备、同音频下不高于 Qwen3-ASR 的 70% |
| 关键事实召回率 | 20 段评测中 `≥ 85%` |

关键事实评测重点覆盖人名、数字、产品名、结论和行动项。普通话和英语属于承诺范围；方言只记录实测，不进入标准模型承诺。

### 9.2 高级模型

- 延续当前 Qwen3-ASR 0.6B INT8 的 RTF、句后出字、最终处理和录音连续性门槛。
- 只对通过高级模型真机评测的设备做正式稳定性承诺。
- 未通过门槛的设备仍可显示下载入口，但必须明确性能风险。
- 高级模型失败不得降低标准模型和仅录音模式的可用性。

## 10. 测试策略

### 10.1 单元测试

- 模型注册表能够区分标准与高级层级。
- `AsrEngineFactory` 返回正确引擎。
- 会议开始后模型选择不可变。
- Manifest 文件大小和 SHA-256 校验。
- 高级模型更新失败保留旧版本。
- 最终快照记录实际模型。
- 改用标准模型重新转录时保留旧快照直到新快照成功。

### 10.2 组件测试

- 设置页显示标准模型已安装。
- 高级模型未下载、下载中、校验中、已安装、更新失败和空间不足状态。
- 开始会议页继承全局默认。
- 本场模型覆盖不修改全局默认。
- 高级模型不可用时要求用户确认回退。
- 录音中不提供模型切换入口。

### 10.3 真机集成测试

两个模型分别执行：

- 30 分钟连续录音与转录。
- 断网 3 分钟。
- ASR 队列积压。
- 强制终止 App 后恢复。
- 会后完整音频重新转录。
- 证据时间区间回放。

标准模型额外验证最低目标设备的 RTF、能耗和温控；高级模型验证设备支持分级。

### 10.4 对比评测

使用相同 20 段真实会议音频运行两个模型，记录：

- RTF P50/P95。
- 峰值内存。
- 30 分钟能耗。
- 温控状态和降频。
- 字错误和关键事实召回。
- 句后出字延迟。
- 最终转录耗时。

评测结果必须保存原始数据，不能只保存“通过/失败”。

## 11. 隐私与安全

- 两个模型都在设备本地推理。
- 模型文件只存放在 APK 或 App 私有目录。
- 模型 Manifest 使用 TLS 下载并校验 SHA-256。
- APK 和日志不得包含云端 AI 永久密钥。
- 日志可以记录模型 ID、版本、阶段、耗时和错误码，不记录完整音频或完整转录。
- 删除高级模型不触发历史会议数据删除。

## 13. 决策摘要

- 首要目标：低功耗和低端设备稳定性。
- 标准语言范围：普通话与英语。
- 标准模型：Paraformer 中文/英文 Small INT8。
- 高级模型：Qwen3-ASR 0.6B INT8。
- 标准模型随 APK 内置，高级模型按需下载。
- 设置保存默认模型，开始会议时允许本场覆盖。
- 所选模型同时负责会中和会后转录。
- 会议进行中不允许切换模型。
- 回退必须显式确认并记录。
